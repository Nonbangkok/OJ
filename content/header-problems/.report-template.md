# House-template conversion — renderer + two pilots

The 50 header-problem statements move to the "Red Gate" house template. This
pass did the harness work and converted **two** statements
(`hp_que09_reverse`, `hp_pair01_equal`); the other 48 are for later agents.
All 50 `meta.json` titles were made English-only in this pass, because that is
mechanical and must not drift.

Everything below was run in the `oj-content-build` image through `./run.sh`.

## 1. What the renderer now supports

`mdrender.py` is still a closed subset — no Markdown dependency, stable bytes
for wkhtmltopdf — but it now covers the template:

| construct | notes |
|---|---|
| `# ## ### ####` | `## Input :` and friends; the space before the colon is the template's |
| paragraphs, `---` | unchanged |
| `* item` / `- item`, `1. item` | unchanged; used by `## Constraints :` and `## Subtasks :` |
| pipe tables | unchanged; used by `## การทดสอบใน grader :` |
| ```` ```cpp ```` fenced code | unchanged |
| ```` ```sample-input ```` + ```` ```sample-output ```` | **rendered as the template's two-column example table** (ข้อมูลนำเข้า / ข้อมูลส่งออก) |
| `$…$`, `$$…$$` | LaTeX subset, rendered server-side (section 2) |
| `<b> <i> <u> <em> <strong> <code> <sub> <sup> <small> <br>` | attribute-free inline tags, passed through |
| `<div style="page-break-after: always;"></div>` | explicit page break, the reference's own spelling |
| `<!-- … -->` | dropped |

Two deliberate departures from the reference file:

* **No raw block HTML.** The reference hand-writes its example tables in HTML
  with inline styles. Passing arbitrary block HTML through would re-open the
  escaping hole the old renderer closed (`<script>` in a statement) *and*
  would put a second copy of the sample in the statement, which could drift
  from the `sample-input`/`sample-output` fixture `verify.py` runs the starter
  against. So the table is **generated from the fixture** instead, styled by
  `statement/style.css` to look like the template's. Everything else that
  looks like a tag is still escaped into visible text — checked by hand
  against the renderer (`<script>alert(1)</script>` in a statement comes out
  as a visible `&lt;script&gt;…` paragraph), not by a committed test: this
  harness has no test suite of its own.
* **No images.** The reference's `<image src="https://firebasestorage…">` is a
  remote fetch; the build runs offline with `--disable-local-file-access`, and
  no header-problem statement has a figure. Adding one later means adding
  local-file support deliberately, not inheriting a remote fetch.

An unknown LaTeX macro is a **build error**, not passthrough — a typo cannot
quietly print itself into 50 PDFs.

## 2. How math is rendered, and the evidence it survives

wkhtmltopdf 0.12.6 is QtWebKit: KaTeX/MathJax do not run in it, and the image
is offline. So `mdrender.render_math` renders LaTeX **server-side** into plain
HTML + CSS:

* relations and operators → Unicode glyphs (`\leq` → `≤`, `\times` → `×`, …);
* scripts → **Unicode superscript/subscript characters** (`10^9` → `10⁹`,
  `a_i` → `aᵢ`) whenever every character of the script maps;
* `\frac`, `\sqrt` → stacked inline-blocks with a border rule;
* variables → italic, `\log`/`\min`/… upright, thin spaces around relations.

**Why Unicode scripts rather than `<sup>`/`<sub>`.** The first pilot build
failed on exactly this, which is how the design was settled: a CSS-raised
`<sup>` sits on its own baseline, and `pdftotext` then reports it as a
separate line *above* the expression — `$10^9$` came back as a lone `9` three
lines before the `10`. A Unicode superscript is ordinary text on the same
baseline and comes back in order. Measured in the image:

```
UNI-SUP 10⁹ และ 10¹⁸ และ 2³² END      <- in order
TAG-SUP 10 x1 END  ...  9             <- the 9 hoisted to its own line
```

Scripts that do not map (a fraction in an exponent, a Greek letter) still
render, via a `<sup>`/`<sub>` fallback; those expressions are simply not used
as probes. `mdrender.math_probe_text` returns `None` for any expression whose
rendering contains `<sub`, `<sup`, `class="frac"` or `class="sqrt"`, i.e. the
renderer itself decides what is assertable.

**The evidence.** `harness.assert_math_survived` is the math twin of the Thai
probe: it runs `pdftotext` on the finished PDF and requires **every** `$…$`
expression in the statement (after the exclusion above, and at least 3
characters long) to appear in the extracted text, compared whitespace-free so
a line wrap cannot break it. A statement carrying no assertable math fails
too, so the check can never go vacuous. Both `build.py` and `verify.py` print
the probe they found:

```
statement.pdf  84.7 KiB  (Thai check ok: "กลับลำดับของสมาชิกทั้งคิว";
                          math check ok: "10,20,30,40,50" — both found in the
                          text extracted from the PDF)

[ok] statement PDF Thai and math text — "เท่ากันเมื่อสมาชิกทั้งสองตัวเท่ากัน"
     and the rendered math "n≤20,000" found in the text extracted from
     80.4 KiB of PDF
```

**The symbol table is verified, not assumed.** Every entry of
`MATH_SYMBOLS`, `SUPERSCRIPTS` and `SUBSCRIPTS` was round-tripped through
wkhtmltopdf + pdftotext in the image: 119/119 came back. `⟨`, `⟩` and `μ` did
**not** and were removed from the table (an unknown macro now fails the build,
which is better than a box in a PDF). To re-run that probe after adding a
symbol, render one `<p>` per table entry with `statement/style.css` applied,
`pdftotext` it, and require each glyph in the squashed output — about 30 lines,
run as `./run.sh -- python3 <script>` with the script inside the harness
directory (only `/work` is mounted in the container).

* **`harness.subtask_section`.** Now generates `## Subtasks :` as the
  template's numbered list (`1. (50 points) ชุดทดสอบที่ 1–5 : …`) instead of a
  four-column table. The sentence above the list still states the
  stop-on-first-failure rule that makes the prefix sum the real score, and the

  judge's formula.
* **`harness.limits_section` (new).** Generates `## Limits :` from
  `meta.json`, so the limits are not typed into the statement a second time.
  `build.py`'s identification line therefore no longer repeats time/memory; it
  now carries รหัสข้อ / ส่งไฟล์ / ระดับความยาก only.
* **`statement/style.css`.** Added: the `.samples` example table (fixed 50/50
  layout, centred headers, transparent `<pre>`), `.page-break`, and the math
  layout (`.math` nowrap, italic serif variables, `.mrel` spacing, `.frac`
  two-line inline-block with a rule, `.sqrt .rad` overline, `<sub>`/`<sup>`
  fallback metrics). The Thai font stack is untouched.

## 4. Harness contract

The sample fixture contract is **unchanged and now harder to break**: the
`sample-input` / `sample-output` fenced blocks are still the only copy of the
sample, `build.py` still writes them out and `verify.py` still runs the
starter against them — and the example table in the PDF is now rendered from
those same two blocks, so there is no hand-written table to drift.

`verify.py` changed in two small ways, both necessary:

1. `check_pdf` now assembles the statement markdown (it needs the `$…$`
   expressions to know what to look for) and calls
   `assert_statement_survived`, which does one `pdftotext` pass and returns
   both probes. The check is renamed "statement PDF Thai and math text".
2. `assert_thai_survived` now takes the extracted text rather than the PDF
   path, so the two probes share one extraction.

New in `harness.py`: `REQUIRED_SECTIONS` is the new 12-section list;
`_split_title` requires `statement.md` to open with `# <meta.json title>` and
then drops that line (the PDF's H1 is rendered from `meta.json`, so the two
cannot disagree); `{{limits}}` and `{{> author}}` joined `{{subtasks}}` and
`{{> rules}}` as required placeholders.

**The 48 unconverted problems now fail the build**, deliberately and with an
actionable message:

```
BUILD FAILED: hp_vec01_fill: statement.md must start with the title as
"# Vector Fill" (found '## คำอธิบาย')
```

Until the set is converted, build and verify **by id**. `dist/` and
`dist/header-problems.zip` currently hold a mix of two freshly built problems
and 48 stale ones; the zip is only meaningful once the rest are rebuilt.

## 6. Converting one of the remaining 48

The per-section recipe lives in `README.md` ("Converting one of the remaining
48") so it is next to the harness rather than in a report. In short: edit only
`statement.md`; open with `# <the exact meta.json title>`; one or two intro
paragraphs; then `## คำอธิบาย :`, `{{> rules}}`, `## คำอธิบายฟังก์ชัน main :`,
`## Input :`, `## Output :`, `## Examples :` (with `### ตัวอย่างที่ 1` and the
two fenced sample blocks — never a hand-written table), `## คำอธิบายตัวอย่างที่
1`, `## การทดสอบใน grader :`, `## Constraints :`, `{{subtasks}}`, `{{limits}}`,
`{{> author}}`. Write bounds and complexities as LaTeX. Use `hp_que09_reverse`
(long, with a page break) and `hp_pair01_equal` (short) as the models. Then
`./run.sh build <id> && ./run.sh verify <id> --measure`.
