# Priority Queue Third

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัว ปุ่มที่
ดัชนี `i` มีลูกอยู่ที่ดัชนี $2i + 1$ และ $2i + 2$ ลำดับความสำคัญตัดสินด้วย
อ็อบเจกต์เปรียบเทียบ `Comp mLess` โดย `mLess(a, b)` เป็นจริงเมื่อ `a`
<b>สำคัญน้อยกว่า</b> `b` และฮีปรักษาเงื่อนไขว่าทุกปุ่มสำคัญไม่น้อยกว่าลูกของมัน

`Comp` เปลี่ยนความหมายของคำว่า "สำคัญ" ได้ทั้งหมด เช่น
`CP::priority_queue<int, std::greater<int>>` เป็น min-heap และโปรแกรมตรวจยัง
ใช้ฮีปของ struct ที่ <b>ไม่มี `operator<`</b> ดังนั้นการเปรียบเทียบทุกจุดใน
คำตอบของคุณต้องผ่าน `mLess` เท่านั้น

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
T CP::priority_queue<T, Comp>::third() const;
```

ที่คืนสมาชิกที่ <b>สำคัญเป็นอันดับสาม</b> ของฮีป (คือค่าที่ได้จากการเรียก `pop()`
ครั้งที่สาม) ถ้าฮีปมีสมาชิกน้อยกว่าสามตัว ให้
`throw std::out_of_range("index out of range")`

ต้องทำใน <b>$O(1)$</b> คิดอย่างนี้: อันดับสองต้องเป็นลูกของราก ให้ `s` เป็นดัชนีของ
ลูกรากที่สำคัญกว่า (นั่นคืออันดับสอง) และ `o` เป็นลูกรากอีกตัวหนึ่ง สมาชิกทุก
ตัวใน subtree ของ `o` สำคัญไม่เกิน `o` จึงไม่มีทางชนะ `o` ได้ ดังนั้น
<b>ผู้ท้าชิงอันดับสามมีเพียงลูกอีกตัวของรากกับลูกสองตัวของอันดับสอง</b> คือ
`o`, `mData[2s+1]` และ `mData[2s+2]` เท่าที่ดัชนีนั้นมีอยู่จริง แล้วตอบตัวที่
สำคัญที่สุดในกลุ่มนี้

ระวังกรณีที่ลูกของรากสำคัญเท่ากัน และกรณีที่ `mSize` เล็ก ทำให้ดัชนี
`2s + 1` หรือ `2s + 2` ยังไม่มีสมาชิก

ไฟล์ `{{ds}}` ยังมีฟังก์ชัน `take_three()` ที่เขียนไว้ให้แล้วบน `third()` ของคุณ
ซึ่งนำสมาชิกสามตัวที่สำคัญที่สุดออกจากฮีปแล้วคืนตัวที่เป็นอันดับสาม ถ้า
`third()` เลือกผิดตัว ค่าที่ฟังก์ชันนี้คืนก็จะผิดตามไปด้วย

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: `top()` และ `third()` คั่นด้วยช่องว่าง
2. บรรทัดที่สอง: ค่าที่ `take_three()` คืน และ `size()` ที่เหลืออยู่
3. บรรทัดที่สาม: `top()` และ `third()` ของฮีปที่เหลือ

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน <b>ชุดคำสั่ง</b> และ
เรียก `third()` สลับกับ `push`, `pop`, `top`, `size`, `take_three` และการ
คัดลอกฮีป เป็นหลักหมื่นครั้งต่อหนึ่งชุดทดสอบ

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงฮีป<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป

## Output :

มีทั้งหมด $3$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ได้จาก `top()` และ `third()` คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าที่ `take_three()` คืน และ `size()` ที่เหลืออยู่ คั่นด้วยช่องว่าง<br>
บรรทัดที่สาม : แสดงค่าที่ได้จาก `top()` และ `third()` ของฮีปที่เหลือ คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
8
10 70 30 60 20 50 40 70
```

### ข้อมูลออก

```sample-output
70 60
60 5
50 30
```

## คำอธิบายตัวอย่างที่ 1

ฮีปเก็บ `{10, 70, 30, 60, 20, 50, 40, 70}` สองอันดับแรกคือ `70` ทั้งคู่ และ
อันดับสามคือ `60` จากนั้น `take_three()` นำ `70`, `70`, `60` ออก คืนค่า `60`
และเหลือสมาชิก `5` ตัวคือ `{10, 30, 20, 50, 40}` ซึ่งมี `top()` คืน `50` และ
`third()` คืน `30`

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `third` | พิมพ์ค่าที่ `third()` คืน (ถ้ามีสมาชิกน้อยกว่าสามตัว ต้องโยน `std::out_of_range`) |
| `take_three` | พิมพ์ค่าที่ `take_three()` คืน ซึ่งนำสามตัวที่สำคัญที่สุดออกจากฮีป |

หลายบล็อกใช้ค่าจากช่วงที่แคบมาก (เช่น `-30` ถึง `30`) ทำให้มีสมาชิกที่สำคัญ
เท่ากันจำนวนมาก และเมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะตรวจสมบัติของฮีปอีก
ครั้งแล้วไล่นำสมาชิกออกตามลำดับความสำคัญ จึงเป็นการตรวจทั้งฮีป ไม่ใช่แค่ค่าที่
พิมพ์ไป

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกไม่เกิน $n \leq 120{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 16{,}000$ คำสั่ง
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
