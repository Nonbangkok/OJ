# Queue Back

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย <b>ring buffer</b> นั่นคือ
อาเรย์ `mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่
ที่ `mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม เมื่อเดินเลยช่องสุดท้ายของ
อาเรย์แล้วจะวนกลับมาที่ช่องที่ $0$ คลาสนี้ยังมีตัวแปรสมาชิก `int aux` ซึ่งข้อนี้
ไม่จำเป็นต้องใช้

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
const T &CP::queue<T>::back() const;
```

ที่คืนค่าอ้างอิงของ <b>สมาชิกตัวหลังสุด</b> ของคิว คือตัวที่เพิ่งถูก `push` เข้า
มาล่าสุดในบรรดาที่ยังอยู่ในคิว รับประกันว่าทุกครั้งที่เรียก `back` คิวจะไม่ว่าง

สมาชิกตัวหลังสุดอยู่ที่ช่องที่อยู่ก่อนช่องว่างช่องแรกหลังข้อมูล นั่นคือห่างจาก
`mFront` ไปทางขวา $\text{mSize} - 1$ ช่องแบบวนรอบ ข้อควรระวังมีสองข้อ

1. ระยะ `mFront + mSize - 1` อาจเลยปลายอาเรย์ไปแล้ว ต้องวนกลับมาที่ต้นอาเรย์
2. `mFront` ไม่ได้เป็น $0$ เสมอ คิวที่ผ่านการ `push` และ `pop` สลับกันหลายครั้ง
   จะมี `mFront` อยู่กลางอาเรย์และข้อมูลพาดข้ามปลายอาเรย์

ให้สังเกตว่า `back` ไม่เปลี่ยนค่าเมื่อมีการ `pop` (เพราะ `pop` เอาตัวหน้าสุด
ออก) จนกว่าคิวจะเหลือสมาชิกตัวเดียว ซึ่งตอนนั้น `front()` และ `back()` ต้อง
คืนสมาชิกตัวเดียวกัน

ฟังก์ชัน `front`, `push` และ `pop` เขียนไว้ให้เรียบร้อยแล้วในไฟล์ `{{ds}}`
คุณไม่ต้องแก้และแก้ไม่ได้ ไฟล์ `{{submission}}` จึงมีเพียงฟังก์ชัน `back` ที่
ยังว่างอยู่ให้คุณเติม

ฟังก์ชันนี้ต้องทำงานในเวลา <b>$O(1)$</b> ต่อการเรียกหนึ่งครั้ง คือคำนวณตำแหน่ง
ด้วยการหารเอาเศษครั้งเดียว ไม่ใช่เดินจาก `mFront` ไปทีละช่องจนถึงตัวสุดท้าย ใน
ชุดทดสอบ 30% สุดท้ายคิวยาวหลายหมื่นตัวและ grader เรียก `back()` ซ้ำกับคิวทุก
ขนาด วิธีที่เดินทีละช่องใช้เวลา $O(\text{size()})$ ต่อการเรียกหนึ่งครั้ง และจะได้
Time Limit Exceeded

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
คิวตามลำดับ จากนั้นพิมพ์ค่าที่ได้จาก `front()` และ `back()` แล้ว `pop()` สอง
ครั้งและ `push(99)` หนึ่งครั้ง จึงพิมพ์ `front()`, `back()` และ `size()` ส่วนหลัง
นี้มีไว้เพื่อให้เห็นว่า `back` ต้องยังถูกต้องหลังจาก `mFront` ขยับและข้อมูล
พาดข้ามปลายอาเรย์แล้ว

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `back` สลับกับ `push`, `pop`, `front` และ
  `size` หลายครั้ง ไม่ใช่เรียกครั้งเดียวตอนท้าย
* จงใจ `pop` แล้ว `push` ซ้ำ ๆ จนข้อมูลพาดข้ามปลายอาเรย์ แล้วจึงเรียก `back`
* เรียก `back` ตอนที่คิวเหลือสมาชิกตัวเดียว ซึ่งต้องได้ค่าเท่ากับ `front()`
* สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด คือ `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
* คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงคิว

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ได้จาก `front()` และ `back()` คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าของ `front()`, `back()` และ `size()` หลังเรียก `pop()`
สองครั้งและ `push(99)` หนึ่งครั้ง คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
5
10 20 30 40 50
```

```sample-output
10 50
30 99 4
```

## คำอธิบายตัวอย่างที่ 1

คิวเริ่มต้นเป็น $10, 20, 30, 40, 50$ จึงได้ `front()` เป็น $10$ และ `back()`
เป็น $50$ หลังจาก `pop()` สองครั้งและ `push(99)` คิวกลายเป็น $30, 40, 50, 99$
จึงได้ `front()` เป็น $30$, `back()` เป็น $99$ และ `size()` เป็น $4$

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
คิวว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` เข้าท้ายคิว |
| `pop` | นำสมาชิกตัวหน้าสุดออก (ถ้าคิวว่างจะข้ามคำสั่งนี้) |
| `front` | พิมพ์สมาชิกตัวหน้าสุด |
| `back` | พิมพ์สมาชิกตัวหลังสุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกคิว แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |
| `digest` | พิมพ์ค่าสรุปที่คำนวณจาก `front()` และ `back()` ของคิวทุกขนาด |

คำสั่ง `digest` ทำงานบนสำเนาของคิว โดยอ่าน `front()` และ `back()` แล้ว `pop()`
ไปเรื่อย ๆ จนหมดคิว แล้วย่อผลลัพธ์ทั้งหมดเป็นเลขตัวเดียว คำสั่งนี้จึงเรียก
`back` ซ้ำกับคิวทุกขนาดตั้งแต่ขนาดเต็มจนเหลือสมาชิกตัวเดียว

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งหมดด้วย
`front` และ `pop` แล้วพิมพ์จำนวนสมาชิกพร้อมค่าสรุปของลำดับที่ได้ จึงเป็นการ
ตรวจทั้งคิว ไม่ใช่แค่หัวและท้าย

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้น $n \leq 50{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $130{,}000$ คำสั่ง
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $10^6$ สำหรับ `int` และไม่เกิน
  $4 \times 10^9$ สำหรับ `long long`
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
