# Priority Queue Update

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัว ปุ่มที่
ดัชนี `i` มีลูกอยู่ที่ดัชนี $2i + 1$ และ $2i + 2$ และมีพ่ออยู่ที่
$\lfloor (i - 1) / 2 \rfloor$ ลำดับความสำคัญตัดสินด้วยอ็อบเจกต์เปรียบเทียบ `Comp mLess` โดย
`mLess(a, b)` เป็นจริงเมื่อ `a` <b>สำคัญน้อยกว่า</b> `b` และสมบัติของฮีปคือทุก
ปุ่มสำคัญไม่น้อยกว่าลูกของมัน

ไฟล์ `{{ds}}` มีฟังก์ชันช่วยซ่อมฮีปเขียนไว้ให้แล้วสองตัว ซึ่งคุณเรียกใช้ได้

- `fixUp(idx)` ย้ายสมาชิกในช่อง `idx` <b>ขึ้น</b> ไปตามสายพ่อจนถึงตำแหน่งที่
  ถูกต้อง ใช้เวลา $O(\log n)$
- `fixDown(idx)` ย้ายสมาชิกในช่อง `idx` <b>ลง</b> ไปทางลูกที่สำคัญกว่า จนถึง
  ตำแหน่งที่ถูกต้อง ใช้เวลา $O(\log n)$

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
void CP::priority_queue<T, Comp>::update(size_t i, const T &value);
```

ที่เปลี่ยนค่าในช่อง `i` ให้เป็น `value` แล้ว <b>ซ่อมฮีปให้ถูกต้องอีกครั้ง</b>
โดยใช้เวลา <b>$O(\log n)$</b> ถ้า $i \geq$ `mSize` ให้
`throw std::out_of_range("index out of range")` และต้องไม่แก้ข้อมูลใด ๆ

จุดสำคัญของข้อนี้คือ <b>ช่องที่ถูกแก้อาจต้องขึ้นหรือลงก็ได้</b> เพราะค่าเดิมหายไป
แล้ว

- ถ้าค่าใหม่สำคัญกว่าพ่อของมัน มันต้องเลื่อนขึ้น → `fixUp`
- ถ้าค่าใหม่สำคัญน้อยกว่าลูกบางตัวของมัน มันต้องเลื่อนลง → `fixDown`

สมาชิกตัวอื่นทั้งหมดไม่ถูกแตะ และก่อนหน้านี้อาเรย์เป็นฮีปที่ถูกต้องอยู่แล้ว
ดังนั้นมีได้อย่างมากทางเดียวที่ต้องซ่อมจริง ตัดสินด้วยการเทียบกับพ่อครั้งเดียว
ก็พอ (ระวังกรณีค่าใหม่สำคัญ <b>เท่ากับ</b> พ่อ ซึ่งไม่ต้องเลื่อนขึ้น และกรณี
`i == 0` ที่ไม่มีพ่อ)

การเรียก `fixUp` แล้วตามด้วย `fixDown` แบบไม่คิดก็ให้ผลถูกต้องเช่นกัน แต่การ
สร้างฮีปใหม่ทั้งก้อน (เรียก `fixDown` ทุกปุ่ม) ใช้เวลา $O(n)$ ต่อการแก้หนึ่งครั้ง
ซึ่งได้เพียง 50%

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นอ่านค่าอีกสองค่าคือ `a` และ `b` แล้ว

1. เรียก `update(0, a)` (แก้ที่ราก ซึ่งปกติต้องเลื่อนลง) แล้วพิมพ์ `top()`
   กับ `heap_ok()`
2. เรียก `update(size() - 1, b)` (แก้ที่ช่องสุดท้าย ซึ่งปกติต้องเลื่อนขึ้น)
   แล้วพิมพ์ `top()` กับ `heap_ok()`
3. ไล่พิมพ์สมาชิกทั้งหมดด้วย `top()` แล้ว `pop()` จนฮีปว่าง

`heap_ok()` เป็นฟังก์ชันที่เขียนไว้ให้แล้วใน `{{ds}}` ซึ่งตรวจว่าอาเรย์ยังมี
สมบัติของฮีปอยู่หรือไม่ โปรแกรมตรวจของผู้ออกข้อสอบก็เรียกฟังก์ชันนี้หลังการ
แก้ค่าหลายพันครั้ง แล้วยังใช้ฮีปต่อด้วย `push`, `pop`, `top` และการไล่เอา
สมาชิกออกทั้งหมด ดังนั้น `update()` ที่ได้ค่าถูกแต่ทิ้งอาเรย์ไว้ในสภาพที่ไม่ใช่
ฮีปจะถูกจับได้แน่นอน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงฮีป<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป<br>
บรรทัดที่สาม : รับจำนวนเต็ม $a$ ซึ่งเป็นค่าที่จะใส่ในช่อง $0$<br>
บรรทัดที่สี่ : รับจำนวนเต็ม $b$ ซึ่งเป็นค่าที่จะใส่ในช่องสุดท้าย

## Output :

มีทั้งหมด $3$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ได้จาก `top()` และ `heap_ok()` หลังเรียก `update(0, a)` คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าที่ได้จาก `top()` และ `heap_ok()` หลังเรียก `update(size() - 1, b)` คั่นด้วยช่องว่าง<br>
บรรทัดที่สาม : แสดงสมาชิกทั้งหมดของฮีปตามลำดับ โดยวนพิมพ์ `top()` แล้ว `pop()` จนฮีปว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
6
30 10 50 20 40 50
5
99
```

### ข้อมูลออก

```sample-output
50 1
99 1
99 50 40 30 20 10
```

## คำอธิบายตัวอย่างที่ 1

หลัง `push` ทั้งหกตัว อาเรย์ภายในเป็น `50 40 50 10 20 30` การเรียก
`update(0, 5)` <b>แทนที่</b> ค่า `50` ที่รากด้วย `5` ซึ่งต้องเลื่อน <b>ลง</b> ไปอยู่
ชั้นล่าง อาเรย์กลายเป็น `50 40 30 10 20 5` และ `top()` เป็น `50` จากนั้น
`update(5, 99)` แทนที่ค่าในช่องสุดท้าย (ซึ่งขณะนั้นคือ `5`) ด้วย `99` ซึ่งต้อง
เลื่อน <b>ขึ้น</b> ไปเป็นราก ทำให้ `top()` เป็น `99` สุดท้ายเมื่อไล่เอาสมาชิกออก
ทั้งหมดจะได้ `99 50 40 30 20 10` ซึ่งเรียงจากมากไปน้อย

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `update i x` | เรียก `update(i, x)` บนช่องที่มีอยู่จริง (ไม่พิมพ์อะไร) |
| `update_raw i x` | เรียก `update(i, x)` โดยไม่ลดค่า `i` ซึ่งส่วนใหญ่เกินขอบเขตและต้องโยน `std::out_of_range` |
| `burst` | แก้ค่าหลายพันครั้งด้วยดัชนีและค่าที่ grader สุ่มเองจาก seed แล้วพิมพ์ขนาดฮีป, `top()` และผลของ `heap_ok()` |

คำสั่ง `burst` คือหัวใจของชุดข้อมูลใหญ่: มันกินข้อมูลเข้าเพียงบรรทัดเดียว แต่
แก้ค่าหลายพันครั้งบนฮีปที่มีสมาชิกถึงสามแสนตัว เมื่อหมดคำสั่งของบล็อกหนึ่ง
grader จะตรวจสมบัติของฮีปแล้วไล่นำสมาชิกออกตามลำดับความสำคัญ

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $2$ บล็อก
* แต่ละบล็อกมีสมาชิกไม่เกิน $n \leq 300{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 420$ คำสั่ง แต่คำสั่ง `burst` หนึ่งคำสั่งนับเป็นการแก้ค่าได้ถึง $3{,}400$ ครั้ง
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
