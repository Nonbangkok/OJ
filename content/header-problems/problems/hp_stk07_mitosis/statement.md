# Stack Mitosis

คลาส `CP::stack<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลไว้ในอาเรย์ `mData` ที่จองไว้
`mCap` ช่อง โดยใช้งานจริง `mSize` ช่องแรก และสมาชิกตัวบนสุดของสแตกอยู่ที่
`mData[mSize - 1]` ฟังก์ชัน `ensureCapacity(c)` ที่คลาสมีให้จะขยายอาเรย์เมื่อ
$c >$ `mCap` โดย <b>จองอาเรย์ใหม่ คัดลอกข้อมูลไปไว้ที่ใหม่ แล้วลบอาเรย์เดิม</b>

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::stack<T>::mitosis(size_t k);
```

ที่ <b>ทำสำเนาสมาชิก $k$ ตัวบนสุด</b> วางซ้อนขึ้นไปบนสแตกโดย <b>คงลำดับเดิม</b>
ถ้าสแตกจากล่างขึ้นบนเป็น `… c b a` และเรียก `mitosis(3)` จะได้
`… c b a c b a` (ไม่ใช่ `… c b a a b c`) โดย

* $k = 0$ สแตกต้องไม่เปลี่ยนแปลงเลย
* $k \geq \text{size}()$ ให้ทำสำเนาสมาชิกทั้งสแตก (ไม่ใช่ข้อผิดพลาด) ข้อมูลทดสอบมี
  $k$ ที่ใหญ่กว่าจำนวนสมาชิกจริง รวมถึงค่าระดับพันล้าน
* ต้องใช้เวลา <b>$O(k)$</b> และควรขยายความจุของอาเรย์เพียง <b>ครั้งเดียว</b> ต่อการ
  เรียกหนึ่งครั้ง

กับดักสำคัญของข้อนี้คือการขยายอาเรย์ วิธีที่ดูเป็นธรรมชาติที่สุด

```cpp
for (size_t i = 0; i < k; i++)
  push(mData[base + i]);   // ผิด
```

ส่ง <b>การอ้างอิง</b> ของช่องในอาเรย์เข้าไปให้ `push` ซึ่งอาจเรียก
`ensureCapacity` ย้ายอาเรย์ทั้งก้อนไปที่ใหม่แล้วลบอาเรย์เดิมทิ้ง การอ้างอิง
ที่ส่งไปจึงชี้ไปยังหน่วยความจำที่ถูกคืนแล้วกลางลูป ข้อมูลทดสอบมีการเรียก
`mitosis` ตอนที่ `mSize` เท่ากับ `mCap` พอดีอยู่หลายครั้ง

โจทย์ข้อนี้ย้าย `top`, `push` และ `pop` มาไว้ใน `{{submission}}` ด้วย คุณจึง
แก้ได้ถ้าจำเป็น แต่ทั้งสามต้องยังทำงานถูกต้องตามความหมายเดิม เพราะโปรแกรม
ตรวจเรียกใช้งานสลับกับ `mitosis` ตลอด

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
สแตกตามลำดับ จากนั้นเรียก `mitosis(2)` และพิมพ์ `size()` แล้วเรียก
`mitosis(1000)` ซึ่งมากกว่าจำนวนสมาชิกและพิมพ์ `size()` อีกครั้ง สุดท้ายพิมพ์
สมาชิกทั้งหมดโดยวนพิมพ์ `top()` แล้ว `pop()` จนสแตกว่าง

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `mitosis` สลับกับ `push`, `pop`, `top`, `size`
  หลายครั้ง ดังนั้นถ้าคุณแก้ `push`, `pop` หรือ `top` แล้วทำให้พฤติกรรมเดิม
  เสียไป ระบบจะจับได้
* พิมพ์จำนวนสมาชิกทุกครั้งหลังเรียก `mitosis` เพื่อตรวจว่าทำสำเนาไปกี่ตัว
  ก่อนที่การไล่พิมพ์ทั้งสแตกจะตรวจว่าทำสำเนาตัวไหน
* สร้างสแตกจากชนิดข้อมูลมากกว่าหนึ่งชนิด เช่น `CP::stack<int>`,
  `CP::stack<std::string>` และ `CP::stack<long long>`
* คัดลอกสแตกด้วย copy constructor และ copy assignment แล้วตรวจว่าสแตกต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงสแตก<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงสแตก

## Output :

มีทั้งหมด $3$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าจาก `size()` หลังเรียก `mitosis(2)`<br>
บรรทัดที่สอง : แสดงค่าจาก `size()` หลังเรียก `mitosis(1000)` ซึ่งมากกว่าจำนวน
สมาชิก<br>
บรรทัดที่สาม : แสดงสมาชิกทั้งหมด โดยวนพิมพ์ `top()` แล้ว `pop()` จนสแตกว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
3
10 20 30
```

```sample-output
5
10
30 20 30 20 10 30 20 30 20 10
```

## คำอธิบายตัวอย่างที่ 1

เริ่มจากสแตก (ล่าง → บน) $10, 20, 30$

* `mitosis(2)` ทำสำเนาสองตัวบนสุด ($20, 30$) ได้ $10, 20, 30, 20, 30$ มี $5$ ตัว
* `mitosis(1000)` มากกว่าจำนวนสมาชิก จึงทำสำเนาทั้งสแตก ได้
  $10, 20, 30, 20, 30, 10, 20, 30, 20, 30$ มี $10$ ตัว

เมื่อพิมพ์จากบนลงล่างจึงได้ $30, 20, 30, 20, 10, 30, 20, 30, 20, 10$

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
สแตกว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงบนสแตก |
| `pop` | นำสมาชิกตัวบนสุดออก (ถ้าสแตกว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกตัวบนสุด หรือ `-` ถ้าสแตกว่าง |
| `size` | พิมพ์จำนวนสมาชิก |
| `mitosis k` | เรียก `mitosis(k)` แล้วพิมพ์จำนวนสมาชิกที่ได้ |
| `copy` | คัดลอกสแตก แล้วพิมพ์ข้อมูลของสำเนา โดยสแตกต้นฉบับต้องไม่เปลี่ยน |
| `fold` | เรียก `top()` แล้วนำค่าไปรวมใน hash ของบล็อก (ไม่พิมพ์อะไร) |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากสแตกทั้งหมด แล้ว
พิมพ์สมาชิก $100$ ตัวแรกที่นำออก ตามด้วยค่า hash ของสมาชิกทุกตัวที่เคยถูกอ่าน
การตรวจลำดับของบล็อกที่ทำสำเนาจึงอาศัยลำดับทั้งสแตก

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้น $n \leq 30{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 90{,}000$ คำสั่ง
* จำนวนสมาชิกในสแตกไม่เกิน $60{,}000$ ตัวตลอดการทำงาน
* ค่า $k$ ไม่เกิน $4 \times 10^9$
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
