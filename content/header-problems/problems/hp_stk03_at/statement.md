## คำอธิบาย

คลาส `CP::stack<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลไว้ในอาเรย์ `mData` ที่จองไว้
`mCap` ช่อง โดยใช้งานจริง `mSize` ช่องแรก สมาชิกตัวที่ใส่เข้ามาก่อนอยู่ที่
ดัชนีน้อย และสมาชิกตัวบนสุดของสแตกอยู่ที่ `mData[mSize - 1]`
ฟังก์ชัน `push`, `pop` และ `top` เขียนไว้ให้แล้วในไฟล์ `{{ds}}`

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
const T &CP::stack<T>::at(size_t k) const;
```

ที่คืนค่าสมาชิกลำดับที่ `k` เมื่อ **นับจากตัวบนสุดลงไป** โดยให้ `k = 0`
หมายถึงตัวบนสุด (ค่าเดียวกับ `top()`), `k = 1` หมายถึงตัวที่อยู่ใต้ตัวบนสุด
และ `k = size() - 1` หมายถึงตัวล่างสุดของสแตก ต้องใช้เวลา **O(1)** ต่อการ
เรียกหนึ่งครั้ง และคืนค่าเป็นการอ้างอิง (reference) ไปยังสมาชิกตัวนั้น

สิ่งที่ต้องคิดคือ `k` นับสวนทางกับดัชนีของ `mData` ดัชนีในอาเรย์จึงเป็นการ
สะท้อนกลับของ `k` ไม่ใช่ `k` ตรง ๆ และ **ห้ามไล่วนลูป** เพราะต้องได้เวลา
O(1) แม้ `k` จะใหญ่ถึงหลักหมื่น

โปรแกรมของผู้ออกข้อสอบจะเรียก `at(k)` เฉพาะเมื่อ `k < size()` เท่านั้น คุณจึง
ไม่ต้องตรวจขอบเขตหรือโยน exception

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงสแตก
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: `at(0)`, `at(1)` และ `at(size() - 1)` คั่นด้วยช่องว่าง
2. บรรทัดที่สอง: `at(0)` และ `at(size() - 1)` หลังเรียก `pop()` หนึ่งครั้ง
3. บรรทัดที่สาม: จำนวนสมาชิกที่เหลือจาก `size()`

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

- อ่าน **ชุดคำสั่ง** และเรียก `at(k)` สลับกับ `push`, `pop`, `top`, `size`
  หลายครั้ง ค่า `k` เดิมจึงหมายถึงสมาชิกต่างตัวกันหลังสแตกเปลี่ยนไป
- ใช้ค่า `k` ทั้งสองปลาย คือ `k = 0` และ `k = size() - 1` บ่อยเป็นพิเศษ
- มีคำสั่งที่ไล่อ่านทั้งสแตกด้วย `at(0)` ถึง `at(size() - 1)` แล้วนำทุกค่าไป
  รวมเป็น hash ดังนั้น `at()` ที่ถูกเฉพาะใกล้ยอดสแตกจะไม่ผ่าน
- สร้างสแตกจากชนิดข้อมูลมากกว่าหนึ่งชนิด เช่น `CP::stack<int>`,
  `CP::stack<std::string>` และ `CP::stack<long long>`
- คัดลอกสแตกด้วย copy constructor และ copy assignment แล้วตรวจว่าสแตกต้นฉบับ
  ไม่เปลี่ยน

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
5
10 20 30 40 50
```

### ข้อมูลออก

```sample-output
50 40 10
40 10
4
```

สแตกจากล่างขึ้นบนคือ `10 20 30 40 50` ดังนั้น `at(0)` คือ `50`, `at(1)` คือ
`40` และ `at(4)` ซึ่งเป็นตัวล่างสุดคือ `10` หลัง `pop()` หนึ่งครั้ง `at(0)`
กลายเป็น `40` ส่วนตัวล่างสุดยังเป็น `10` และเหลือสมาชิก `4` ตัว

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
สแตกว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงบนสแตก |
| `pop` | นำสมาชิกตัวบนสุดออก (ถ้าสแตกว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกตัวบนสุด |
| `at k` | พิมพ์ `at(k)` โดยข้อมูลรับประกันว่า `k < size()` |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกสแตก แล้วพิมพ์และไล่อ่านสำเนาด้วย `at()` โดยสแตกต้นฉบับต้องไม่เปลี่ยน |
| `fold k` | เรียก `at(k)` แล้วนำค่าไปรวมใน hash ของบล็อก (ไม่พิมพ์อะไร) |
| `sweep` | ไล่อ่าน `at(0)` ถึง `at(size() - 1)` แล้วนำทุกค่าไปรวมใน hash |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากสแตกทั้งหมด แล้ว
พิมพ์สมาชิก 100 ตัวแรกที่นำออก ตามด้วยค่า hash ของสมาชิกทุกตัวที่เคยถูกอ่าน

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมีสมาชิกเริ่มต้น
`n` ตัว โดย `n ≤ 50,000` และมีคำสั่งไม่เกิน `q ≤ 120,000` คำสั่ง สมาชิกชนิด
จำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน 4 × 10⁹ และสมาชิกชนิดข้อความเป็นตัวอักษร
ภาษาอังกฤษตัวเล็กยาวไม่เกิน 6 ตัว
