# Queue Pop Back

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย <b>ring buffer</b> นั่นคือ
อาเรย์ `mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่
ที่ `mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม เมื่อเดินเลยช่องสุดท้ายของ
อาเรย์แล้วจะวนกลับมาที่ช่องที่ $0$ คลาสนี้ยังมีตัวแปรสมาชิก `int aux` ซึ่งข้อนี้
ไม่จำเป็นต้องใช้

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::queue<T>::pop_back();
```

ที่นำ <b>สมาชิกตัวหลังสุด</b> ออกจากคิว สมาชิกที่เหลือต้องยังเรียงเหมือนเดิมและ
ตัวหน้าสุดต้องยังเป็นตัวเดิม ถ้าเรียกกับคิวที่ว่างอยู่แล้วต้องไม่ทำอะไรเลย
และคิวต้องยังใช้งานต่อได้ตามปกติ

ข้อนี้เป็นเรื่องของการมองให้ออกว่า <b>ไม่ต้องย้ายข้อมูลเลย</b> ขอบเขตของคิวใน
อาเรย์ถูกกำหนดด้วย `mFront` กับ `mSize` เท่านั้น ตัวหลังสุดอยู่ที่ระยะ
$\text{mSize} - 1$ จาก `mFront` ดังนั้นการตัดมันออกคือการบอกว่าคิวสั้นลงหนึ่ง
ตัว ไม่ใช่การเลื่อนอะไร และ `mFront` ต้องอยู่นิ่ง เพราะถ้าขยับ `mFront` จะกลาย
เป็นการเอาตัว <b>หน้าสุด</b> ออกแทน

สิ่งที่พลาดกันบ่อยคือกรณีคิวว่าง ตัวแปร `mSize` มีชนิด `size_t` ซึ่งเป็น
จำนวนเต็มไม่มีเครื่องหมาย การลดค่ามันตอนที่เป็น $0$ จะไม่ได้ $-1$ แต่จะวนไป
เป็นเลขมหาศาล คิวจะอ้างว่าตัวเองมีสมาชิกเป็นหมื่นล้านล้านตัว และทุกคำสั่ง
ถัดจากนั้นก็พังตามไปด้วย ผู้ออกข้อสอบเรียก `pop_back` กับคิวว่างแน่นอน

ฟังก์ชัน `front`, `back`, `push` และ `pop` เขียนไว้ให้เรียบร้อยแล้วในไฟล์
`{{ds}}` คุณไม่ต้องแก้และแก้ไม่ได้ ไฟล์ `{{submission}}` จึงมีเพียงฟังก์ชัน
`pop_back` ที่ยังว่างอยู่ให้คุณเติม

ฟังก์ชันนี้ต้องทำงานในเวลา <b>$O(1)$</b> ต่อการเรียกหนึ่งครั้ง การไล่เดินจาก
`mFront` ไปหาช่องของตัวหลังสุดก่อนจะตัดมันออกให้คำตอบถูกต้อง แต่ใช้เวลา
$O(\text{size()})$ ทุกครั้ง และจะได้ Time Limit Exceeded ในชุดทดสอบ 30% สุดท้าย

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
คิวตามลำดับ จากนั้นอ่านจำนวน $m$ แล้วเรียก `pop_back()` ซ้ำ $m$ ครั้ง โดย $m$
อาจมากกว่าจำนวนสมาชิกที่มีก็ได้ แล้วพิมพ์ `size()` จากนั้น `push(77)` และ
`push(88)` แล้วพิมพ์ `front()`, `back()` และ `size()` ตามด้วยสมาชิกทั้งหมดของ
คิว

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `pop_back` สลับกับ `push`, `pop`, `front`,
  `back` และ `size` หลายครั้ง
* เรียก `pop_back` ติดต่อกันจนคิวว่างและเรียกเกินไปอีกหลายครั้ง แล้วจึง
  `push` ของใหม่เข้าไปใช้งานต่อ
* สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด คือ `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
* คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงคิว<br>
บรรทัดที่สาม : รับจำนวนเต็ม $m$ แทนจำนวนครั้งที่จะเรียก `pop_back()`

## Output :

มีทั้งหมด $3$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าของ `size()` หลังการเรียก `pop_back` ทั้งหมด<br>
บรรทัดที่สอง : แสดงค่าของ `front()`, `back()` และ `size()` หลังจาก `push(77)`
และ `push(88)` คั่นด้วยช่องว่าง<br>
บรรทัดที่สาม : แสดงสมาชิกทั้งหมดตามลำดับ โดยวนพิมพ์ `front()` แล้ว `pop()` จน
คิวว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
5
10 20 30 40 50
6
```

```sample-output
0
77 88 2
77 88
```

## คำอธิบายตัวอย่างที่ 1

คิวมีสมาชิก $5$ ตัว แต่ถูกเรียก `pop_back()` ถึง $6$ ครั้ง ห้าครั้งแรกเอา
สมาชิกออกทีละตัวจนคิวว่าง ครั้งที่หกเป็นการเรียกกับคิวว่าง ซึ่งต้องไม่ทำอะไร
จึงได้ `size()` เป็น $0$ หลังจากนั้นคิวต้องยังใช้งานได้ `push(77)` และ
`push(88)` ทำให้คิวเป็น $77, 88$

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
คิวว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` เข้าท้ายคิว |
| `pop` | นำสมาชิกตัวหน้าสุดออก (ถ้าคิวว่างจะข้ามคำสั่งนี้) |
| `pop_back` | เรียก `pop_back()` โดยไม่ตรวจก่อนว่าคิวว่างหรือไม่ |
| `front` | พิมพ์สมาชิกตัวหน้าสุด |
| `back` | พิมพ์สมาชิกตัวหลังสุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกคิว แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |
| `digest` | พิมพ์ค่าสรุปที่คำนวณจากสมาชิกทุกตัวเรียงจากหน้าไปหลัง |

ให้สังเกตว่าคำสั่ง `pop_back` ของ grader <b>ไม่</b> ตรวจก่อนว่าคิวว่างหรือเปล่า
ต่างจากคำสั่ง `pop` ที่ grader ข้ามให้เมื่อคิวว่าง การรับมือกับคิวว่างจึง
เป็นหน้าที่ของฟังก์ชันที่คุณเขียน

คำสั่ง `digest` ทำงานบนสำเนาของคิว โดยอ่าน `front()` แล้ว `pop()` ไปเรื่อย ๆ
จนหมดคิว แล้วย่อลำดับทั้งหมดเป็นเลขตัวเดียว ถ้ามีสมาชิกตัวใดอยู่ผิดตำแหน่ง
หรือจำนวนสมาชิกเพี้ยนไป ค่านี้จะเปลี่ยนไปทันที

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งหมดด้วย
`front` และ `pop` แล้วพิมพ์จำนวนสมาชิกพร้อมค่าสรุปของลำดับที่ได้

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้น $n \leq 60{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $155{,}000$ คำสั่ง
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $10^6$ สำหรับ `int` และไม่เกิน
  $4 \times 10^9$ สำหรับ `long long`
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
