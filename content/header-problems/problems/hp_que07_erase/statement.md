## คำอธิบาย

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย **ring buffer**: อาเรย์
`mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่ที่
`mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม เมื่อเดินเลยช่องสุดท้ายของ
อาเรย์แล้วจะวนกลับมาที่ช่องที่ 0 ดังนั้นสมาชิกลำดับที่ `i` นับจากหน้าสุดอยู่
ที่ `mData[(mFront + i) % mCap]`

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::queue<T>::erase(size_t i);
```

ที่ลบสมาชิกลำดับที่ `i` นับจากหน้าสุด (นับเริ่มจาก 0) ออกจากคิว สมาชิกที่
เหลือต้องยังเรียงลำดับเดิมสัมพันธ์กัน และ `size()` ลดลงหนึ่ง รับประกันว่าทุก
ครั้งที่เรียกจะมี `0 ≤ i < size()` เสมอ

ตัวอย่างเช่น คิว `A B C D E` เมื่อ `erase(1)` จะได้ `A C D E`

ข้อสำคัญคือ **เวลาที่ใช้** ฟังก์ชันนี้ต้องใช้เวลา

```cpp
O(min(i, size() - 1 - i))
```

นั่นคือห้ามเกินจำนวนสมาชิกของฝั่งที่สั้นกว่า เพราะการลบสมาชิกกลางคิวใน ring
buffer ทำได้สองทาง และต้นทุนไม่เท่ากัน

1. เลื่อนทุกตัว **ที่อยู่หลัง** ตำแหน่ง `i` ขึ้นมาข้างหน้าหนึ่งตำแหน่ง แล้ว
   ลด `mSize` ลงหนึ่ง ต้นทุนคือ `size() - 1 - i`
2. เลื่อนทุกตัว **ที่อยู่ก่อน** ตำแหน่ง `i` ถอยหลังไปหนึ่งตำแหน่ง แล้วขยับ
   `mFront` ไปทางขวาหนึ่งช่องแบบวนรอบ และลด `mSize` ลงหนึ่ง ต้นทุนคือ `i`

ทั้งสองทางให้ผลลัพธ์เหมือนกัน คำตอบที่ผ่านทุกชุดทดสอบจึงต้องดูค่า `i` เทียบ
กับ `size() - 1 - i` แล้ว **ย้ายข้อมูลเพียงฝั่งที่สั้นกว่า** ผู้ออกข้อสอบจงใจ
ให้คำสั่งส่วนใหญ่ในชุดทดสอบใหญ่เป็นการลบที่อยู่ใกล้หัวคิวหรือใกล้ท้ายคิว
ดังนั้นโปรแกรมที่เลือกทางเดียวตายตัวจะเสียเวลาเท่ากับความยาวคิวแทบทุกครั้ง
และจะได้ Time Limit Exceeded ในชุดทดสอบ 50% หลัง

ข้อควรระวังอีกข้อคือทุกการคำนวณตำแหน่งต้องวนรอบด้วย `% mCap` เพราะช่วงที่ต้อง
เลื่อนอาจเริ่มที่ท้ายอาเรย์แล้วไปจบที่ต้นอาเรย์ และตอนขยับ `mFront` ก็ต้องวน
รอบเช่นกัน

ฟังก์ชัน `front`, `back`, `push` และ `pop` เขียนไว้ให้เรียบร้อยแล้วในไฟล์
`{{ds}}` คุณไม่ต้องแก้และแก้ไม่ได้ ไฟล์ `{{submission}}` จึงมีเพียงฟังก์ชัน
`erase` ที่ยังว่างอยู่ให้คุณเติม นอกจากนี้คลาสยังมีตัวแปรสมาชิก `int aux`
ซึ่งข้อนี้ไม่จำเป็นต้องใช้

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงคิว
ตามลำดับ จากนั้นอ่านจำนวนคำสั่ง `m` และดัชนี `m` ตัว แล้วเรียก `erase(i)` ตาม
ลำดับ สุดท้ายพิมพ์

1. บรรทัดแรก: `front()`, `back()` และ `size()` คั่นด้วยช่องว่าง
2. บรรทัดที่สอง: สมาชิกทั้งหมด โดยวนพิมพ์ `front()` แล้ว `pop()` จนคิวว่าง

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

- อ่าน **ชุดคำสั่ง** และเรียก `erase` สลับกับ `push`, `pop`, `front`, `back`
  และ `size` หลายครั้ง โดยมีการ `push` แทรกเพื่อให้คิวยังยาวอยู่เสมอ
- จงใจ `pop` แล้ว `push` ซ้ำ ๆ จนคิวพาดข้ามปลายอาเรย์ก่อนสั่งลบ
- ใช้ `i` ที่เป็น 0, `i` ที่เป็น `size() - 1` และ `i` ที่อยู่ใกล้ปลายทั้งสอง
  ข้าง รวมทั้งบางส่วนที่อยู่กลางคิว
- สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด คือ `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
- คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
6
10 20 30 40 50 60
3
0 3 1
```

### ข้อมูลออก

```sample-output
20 60 3
20 40 60
```

เริ่มจากคิว `10 20 30 40 50 60`

1. `erase(0)` ลบสมาชิกลำดับที่ 0 คือ `10` เหลือ `20 30 40 50 60` ครั้งนี้
   ฝั่งหัวสั้นกว่า (ต้นทุน 0) จึงเลื่อนฝั่งหัวแล้วขยับ `mFront`
2. `erase(3)` ทำกับคิวที่เหลือ สมาชิกลำดับที่ 3 คือ `50` เหลือ
   `20 30 40 60` ครั้งนี้ฝั่งท้ายสั้นกว่า (ต้นทุน 1)
3. `erase(1)` สมาชิกลำดับที่ 1 คือ `30` เหลือ `20 40 60`

ให้สังเกตว่าดัชนีแต่ละครั้งนับกับคิว ณ ขณะนั้น ไม่ใช่คิวตั้งต้น

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
คิวว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` เข้าท้ายคิว |
| `pop` | นำสมาชิกตัวหน้าสุดออก (ถ้าคิวว่างจะข้ามคำสั่งนี้) |
| `erase i` | เรียก `erase(i)` |
| `front` | พิมพ์สมาชิกตัวหน้าสุด |
| `back` | พิมพ์สมาชิกตัวหลังสุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกคิว แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |
| `digest` | พิมพ์ค่าสรุปที่คำนวณจากสมาชิกทุกตัวเรียงจากหน้าไปหลัง |

คำสั่ง `digest` ทำงานบนสำเนาของคิว โดยอ่าน `front()` แล้ว `pop()` ไปเรื่อย ๆ
จนหมดคิว แล้วย่อลำดับทั้งหมดเป็นเลขตัวเดียว การลบที่ทำให้สมาชิกตัวอื่นหายไป
ซ้ำขึ้นมา หรืออยู่ผิดตำแหน่ง จะเปลี่ยนค่านี้ทันที

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งหมดด้วย
`front` และ `pop` แล้วพิมพ์จำนวนสมาชิกพร้อมค่าสรุปของลำดับที่ได้

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมีสมาชิกเริ่มต้น
`n ≤ 60,000` ตัว และมีคำสั่งไม่เกิน 80,000 คำสั่ง สมาชิกชนิดจำนวนเต็มมีค่า
สัมบูรณ์ไม่เกิน 10⁶ สำหรับ `int` และไม่เกิน 4 × 10⁹ สำหรับ `long long`
ส่วนสมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน 6 ตัว
