## คำอธิบาย

คลาส `CP::pair<T1,T2>` ในไฟล์ `{{ds}}` เก็บข้อมูลสองตัวไว้ในตัวแปรสมาชิก
`T1 first` และ `T2 second`

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T1, typename T2>
bool CP::pair<T1, T2>::operator>=(const CP::pair<T1, T2> &other) const;
```

ที่คืนค่า `true` เมื่อ `*this` **มากกว่าหรือเท่ากับ** `other` ตามลำดับแบบ
พจนานุกรม นั่นคือเทียบ `first` ก่อน ถ้า `first` เท่ากันจึงเทียบ `second`
เขียนเป็นเงื่อนไขได้ว่าต้องคืน `true` เมื่อ

- `first` ของ `*this` มากกว่า `first` ของ `other` หรือ
- `first` ของทั้งสองคู่เท่ากัน และ `second` ของ `*this` มากกว่าหรือเท่ากับ
  `second` ของ `other`

จุดที่พลาดกันบ่อยคือขอบของเครื่องหมาย เพราะ คู่อันดับที่เท่ากันทุกตำแหน่งต้อง
คืนค่าจริง ข้อนี้จึงมีข้อมูลทดสอบที่เป็นคู่เท่ากันจำนวนมาก รวมถึงการเทียบ
คู่อันดับกับตัวมันเอง ซึ่งต้องได้ `true` เสมอ

ชนิด `T1` และ `T2` รับประกันว่ามีตัวดำเนินการ `<` และ `==` ของตัวเองอยู่แล้ว
แต่ไม่รับประกันว่ามี `>=` ดังนั้นให้สร้างผลลัพธ์จาก `<` หรือ `==` ของสมาชิก

คลาสนี้ยังมีตัวดำเนินการ `<` และ `<=` ซึ่งเขียนไว้ให้แล้วในไฟล์ `{{ds}}` โดย
`a < b` นิยามเป็นนิเสธของ `a >= b` และ `a <= b` นิยามเป็น `b >= a` ทั้งสอง
ตัวจึงทำงานบน `>=` ของคุณทั้งหมด และในไฟล์ `{{submission}}` มีฟังก์ชัน
`clamp_low` ที่ยกค่าของคู่อันดับขึ้นมาเป็นค่าขั้นต่ำที่กำหนด ถ้าตอนนี้ยังน้อย
กว่าค่านั้น ซึ่งเขียนไว้ถูกต้องแล้ว คุณแก้ได้แต่ต้องคงความหมายเดิมไว้

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนคู่อันดับ `n` แล้วอ่านคู่อันดับชนิด
`CP::pair<int,int>` มา `n` คู่ คู่แรกถูกใช้เป็นค่าขั้นต่ำ สำหรับคู่ที่เหลือ
โปรแกรมจะพิมพ์สองบรรทัดต่อหนึ่งคู่ คือ

1. ผลของ `>=` และ `<` เทียบกับค่าขั้นต่ำ เป็น `1` หรือ `0`
2. ค่าของคู่อันดับนั้นหลังเรียก `clamp_low` ด้วยค่าขั้นต่ำ

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

- อ่าน ชุดคำสั่ง แล้วเรียก `>=`, `<`, `<=`, `clamp_low`, คอนสตรักเตอร์ และ
  การคัดลอกคู่อันดับสลับกันไปมา
- สร้างคู่อันดับจากชนิดข้อมูลสามแบบ คือ `CP::pair<int,int>`,
  `CP::pair<std::string,std::string>` และ `CP::pair<long long,int>`
- พิมพ์ผลของ `>=`, `<` และ `<=` พร้อมกันทุกครั้ง คู่อันดับที่เท่ากันจึงต้อง
  ได้ `1 0 1` และคู่ที่ต่างกันต้องได้ `1 0 0` หรือ `0 1 1`
- เทียบคู่อันดับกับตัวมันเอง และเทียบกับสำเนาที่สร้างด้วย copy constructor
  ซึ่งทั้งสองกรณีต้องได้ `1 0 1`

ดังนั้นถ้าคุณแก้ `clamp_low` แล้วทำให้พฤติกรรมเดิมของฟังก์ชันนั้นเสียไป
ระบบจะจับได้

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
4
2 5
2 5
2 4
9 0
```

### ข้อมูลออก

```sample-output
1 0
2 5
0 1
2 5
1 0
9 0
```

ค่าขั้นต่ำคือ `(2, 5)` คู่ที่สองเท่ากับค่าขั้นต่ำพอดี `>=` จึงเป็นจริงและ
`clamp_low` ไม่เปลี่ยนอะไร คู่ที่สาม `(2, 4)` มี `first` เท่ากันแต่ `second`
น้อยกว่า จึงน้อยกว่าค่าขั้นต่ำและถูกยกขึ้นเป็น `(2, 5)` คู่ที่สี่ `(9, 0)` มี
`first` มากกว่าจึงมากกว่าทันที แม้ `second` จะน้อยกว่า

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกระบุชนิด
ข้อมูลของตัวเอง แล้วสร้างอาเรย์ของคู่อันดับ `n` ตัว หลังจากนั้นจะมีคำสั่งผสมกัน
ดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `cmp i j` | พิมพ์ผลของ `A[i] >= A[j]`, `A[i] < A[j]` และ `A[i] <= A[j]` |
| `assign i a b` | ทำ `A[i] = CP::pair(a, b)` ด้วยการคัดลอก |
| `clamp i j` | เรียก `A[i].clamp_low(A[j])` แล้วพิมพ์ค่าของ `A[i]` |
| `temp i a b` | เทียบ `A[i]` กับคู่อันดับชั่วคราวที่สร้างจาก `(a, b)` |
| `self i` | เทียบ `A[i]` กับตัวมันเอง |
| `zero i` | เทียบ `A[i]` กับคู่อันดับที่สร้างจากคอนสตรักเตอร์ว่าง |
| `copy i` | เทียบสำเนาที่สร้างด้วย copy constructor กับ `A[i]` |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะวนเทียบคู่อันดับที่อยู่ติดกันทั้งอาเรย์
แล้วพิมพ์จำนวนตำแหน่งที่ `>=` เป็นจริง จำนวนที่ `<` เป็นจริง และจำนวนที่ `<=`
เป็นจริง สองจำนวนแรกต้องรวมกันได้เท่ากับจำนวนตำแหน่งทั้งหมดเสมอ

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมี `n ≤ 20,000` และ
มีคำสั่งไม่เกิน `q ≤ 40,000` คำสั่ง สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน
`10^9` สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน `4 × 10^9` และสมาชิกชนิด
ข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน 6 ตัว
