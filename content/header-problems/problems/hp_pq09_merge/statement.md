# Priority Queue Merge

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์ `mData` ซึ่งมีที่ว่าง `mCap` ช่องและเก็บ
สมาชิก `mSize` ตัว ปุ่มที่ดัชนี `i` มีลูกอยู่ที่ดัชนี $2i + 1$ และ $2i + 2$
ลำดับความสำคัญตัดสินด้วย `Comp mLess` และสมบัติของฮีปคือทุกปุ่มสำคัญไม่น้อย
กว่าลูกของมัน ไฟล์ `{{ds}}` มีฟังก์ชันเตรียมไว้ให้เรียกใช้ได้แล้วคือ
`ensureCapacity(cap)` (ขยายอาเรย์ให้มีที่อย่างน้อย `cap` ช่อง),
`fixUp(idx)` และ `fixDown(idx)`

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
void CP::priority_queue<T, Comp>::merge(priority_queue<T, Comp> &other);
```

ที่ <b>ย้ายสมาชิกทุกตัวของ `other` เข้ามาอยู่ในฮีปนี้</b> แล้วทำให้ฮีปนี้ยังถูก
ต้อง และทำให้ `other` <b>ว่างเปล่า</b> (`other.size() == 0`) เมื่อเสร็จ โดยใช้
เวลา <b>$O(n + m)$</b> เมื่อ `n` คือจำนวนสมาชิกของฮีปนี้และ `m` คือจำนวนสมาชิกของ
`other`

เนื่องจาก `other` เป็นอ็อบเจกต์ของคลาสเดียวกัน คุณเข้าถึงตัวแปรสมาชิกที่เป็น
`protected` ของมันได้โดยตรง เช่น `other.mData`, `other.mSize`

วิธีที่ได้ $O(n + m)$ มีสองขั้น

1. <b>ขยายที่เพียงครั้งเดียว</b> เรียก `ensureCapacity(mSize + other.mSize)`
   หนึ่งครั้ง แล้วคัดลอก `other.mData[0..other.mSize-1]` ไปต่อท้าย
   `mData` ตามเดิมโดยไม่ต้องจัดเรียง แล้วเพิ่ม `mSize`
2. <b>สร้างฮีปจากล่างขึ้นบนด้วยการเรียก `fixDown` ทุกปุ่มที่มีลูก</b> โดยไล่
   <b>จากปุ่มที่มีลูกตัวสุดท้ายย้อนกลับมาถึงดัชนี `0`</b> ขั้นนี้ใช้เวลารวม
   $O(n + m)$ ไม่ใช่ $O((n+m) \log(n+m))$ เพราะปุ่มส่วนใหญ่อยู่ชั้นล่างและเลื่อน
   ได้ไม่ไกล

ลำดับการไล่ปุ่มสำคัญมาก: `fixDown(i)` ใช้ได้เฉพาะเมื่อ subtree ทั้งสองข้างของ
`i` เป็นฮีปที่ถูกต้องอยู่แล้ว การไล่จากดัชนี `0` ลงไปหาท้ายอาเรย์จึงให้ผล
<b>ผิด</b> ไม่ใช่แค่ช้า

สิ่งที่ต้องไม่ทำคือ `push` สมาชิกของ `other` เข้ามาทีละตัว วิธีนั้นใช้เวลา
$O(m \log(n + m))$ และได้เพียง 50% เพราะชุดข้อมูลใหญ่ใช้ค่าที่ซ้ำกันมาก ซึ่งเป็น
กรณีที่ `fixUp` ต้องไล่ขึ้นไปจนถึงรากทุกครั้ง (เงื่อนไขหยุดของ `fixUp` คือพ่อ
สำคัญ <b>กว่า</b> อย่างเคร่งครัด สมาชิกที่สำคัญเท่ากันจึงไม่ทำให้หยุด)

กรณีขอบที่ต้องผ่าน: `other` ว่าง (ต้องไม่เปลี่ยนอะไรและต้องไม่อ่าน
`other.mData` เกินขอบ) และ `other` มีสมาชิกมากกว่าฮีปนี้

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่าน `n` กับสมาชิก `n` ตัวมาใส่ฮีป `a` แล้วอ่าน `m` กับ
สมาชิก `m` ตัวมาใส่ฮีป `b` จากนั้น

1. เรียก `a.merge(b)` แล้วพิมพ์ `a.size()`, `b.size()` และ `a.heap_ok()`
2. ไล่พิมพ์สมาชิกทั้งหมดของ `a` ด้วย `top()` แล้ว `pop()` จนว่าง

`heap_ok()` เป็นฟังก์ชันที่เขียนไว้ให้แล้วใน `{{ds}}` ซึ่งตรวจว่าอาเรย์ยังมี
สมบัติของฮีปอยู่หรือไม่

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกของฮีป `a`<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป `a`<br>
บรรทัดที่สาม : รับจำนวนเต็ม $m$ แทนจำนวนสมาชิกของฮีป `b`<br>
บรรทัดที่สี่ : รับจำนวนเต็ม $m$ จำนวน คือ $b_1, b_2, \ldots, b_m$ ตามลำดับที่ `push` ลงฮีป `b`

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่า `a.size()`, `b.size()` และ `a.heap_ok()` หลังเรียก `a.merge(b)` คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงสมาชิกทั้งหมดของฮีป `a` ตามลำดับ โดยวนพิมพ์ `top()` แล้ว `pop()` จนฮีปว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
3
10 50 30
4
60 20 40 70
```

### ข้อมูลออก

```sample-output
7 0 1
70 60 50 40 30 20 10
```

## คำอธิบายตัวอย่างที่ 1

ฮีป `a` มี `{10, 50, 30}` และฮีป `b` มี `{60, 20, 40, 70}` หลัง `merge`
ฮีป `a` มีสมาชิก `7` ตัว ฮีป `b` ว่าง (`0`) อาเรย์ของ `a` ยังมีสมบัติของฮีป
(`1`) และเมื่อไล่เอาสมาชิกออกทั้งหมดจะได้ลำดับจากมากไปน้อย

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีปที่ใช้งาน |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `make_a` / `make_b` | สร้าง "ฮีปต้นแบบ" สองก้อนเก็บไว้ (สร้างครั้งเดียว) |
| `restore` | คัดลอกฮีปต้นแบบก้อนแรกมาเป็นฮีปที่ใช้งาน |
| `merge_b` | เรียก `merge()` ด้วย <b>สำเนา</b> ของฮีปต้นแบบก้อนที่สอง |
| `merge_list` | เรียก `merge()` ด้วยฮีปเล็กที่สร้างจากค่าที่ให้มาในบรรทัดนั้น (มีกรณี 0, 1, 2 สมาชิกด้วย) |
| `merge_empty` | เรียก `merge()` ด้วยฮีปว่าง |

ทุกครั้งที่เรียก `merge()` grader จะพิมพ์จำนวนสมาชิกของฮีปที่ใช้งาน จำนวน
สมาชิกของ `other` (ซึ่งต้องเป็น `0`) ผลของ `heap_ok()` และ `top()` การลืมทำให้
`other` ว่าง หรือการทิ้งอาเรย์ไว้ในสภาพที่ไม่ใช่ฮีป จึงถูกจับได้ทันที

ชุดข้อมูลใหญ่ใช้วิธี `make_b` หนึ่งครั้งแล้ว `restore` + `merge_b` ซ้ำ ๆ
กว่าร้อยครั้ง เพื่อให้สิ่งที่วัดคือเวลาของ `merge()` ไม่ใช่เวลาที่ใช้สร้างฮีป
ต้นทาง และเวลาที่ให้ของข้อนี้คือ 1.5 วินาที

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* ฮีปต้นแบบมีสมาชิกไม่เกิน $262{,}144$ ตัว
* ฮีปต้นแบบถูกรวมซ้ำไม่เกิน $138$ ครั้งต่อบล็อก
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
