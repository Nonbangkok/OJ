## คำอธิบาย

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
**ไบนารีฮีป** (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัวที่ดัชนี
`0` ถึง `mSize - 1` รูปร่างของต้นไม้ถูกกำหนดโดยดัชนีล้วน ๆ คือปุ่มที่ดัชนี
`i` มีลูกอยู่ที่ดัชนี `2i + 1` และ `2i + 2` (เท่าที่ดัชนีนั้นยังไม่เกิน
`mSize`) ต้นไม้ที่ได้จึงเป็น **ต้นไม้ทวิภาคที่เกือบสมบูรณ์** (complete binary
tree) คือทุกชั้นเต็มยกเว้นชั้นล่างสุดที่เต็มจากซ้ายมาขวา

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
size_t CP::priority_queue<T, Comp>::descendants(size_t i) const;
```

ที่คืน **จำนวนลูกหลานทั้งหมด** ของปุ่มที่ดัชนี `i` (ลูก ลูกของลูก ไปจนถึงชั้น
ล่างสุด โดย **ไม่นับตัวมันเอง**) ถ้า `i ≥ mSize` ให้
`throw std::out_of_range("index out of range")`

ข้อนี้บังคับเวลา **O(log n)** ต่อหนึ่งคำถาม การไล่เดินทุกปุ่มใน subtree ได้
เพียง 50% เพราะโปรแกรมตรวจถามดัชนีที่อยู่ **ใกล้ราก** เป็นหลัก ซึ่ง subtree
ของมันเกือบเท่าทั้งอาเรย์

แนวคิดที่ใช้ได้: **ลูกหลานของปุ่มหนึ่งในแต่ละชั้นเป็นช่วงดัชนีที่ติดกัน**
ลูกหลานชั้นที่ `1` ของ `i` คือ `[2i+1, 2i+2]` ชั้นที่ `2` คือ
`[4i+3, 4i+6]` และต่อไปเรื่อย ๆ โดยขอบซ้ายหาได้จากการทำ
`left = 2 × left + 1` ซ้ำ ๆ และขอบขวาจาก `right = 2 × right + 2` ซ้ำ ๆ
แต่ละชั้นจึงนับได้ด้วยการลบกันครั้งเดียว เหลือเพียงระวังชั้นล่างสุดที่อาจถูก
ตัดที่ `mSize - 1` และชั้นที่ขอบซ้ายเลย `mSize` ไปแล้ว (ซึ่งคือจุดที่ต้องหยุด)
จำนวนชั้นมีไม่เกิน `log₂(mSize) + 1` ชั้น

สังเกตว่าคำตอบไม่ขึ้นกับ **ค่า** ของสมาชิกเลย ขึ้นกับ `i` และ `mSize` เท่านั้น
แต่ `mSize` เปลี่ยนไปเรื่อย ๆ ตาม `push` และ `pop` ที่โปรแกรมตรวจเรียกสลับกับ
คำถาม จึงจำคำตอบไว้ล่วงหน้าไม่ได้

ไฟล์ `{{ds}}` ยังมีฟังก์ชัน `is_leaf()` ที่เขียนไว้ให้แล้วเป็น
`descendants(i) == 0`

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: `descendants(i)` ของทุกช่อง `i` ตั้งแต่ `0` ถึง `size() - 1`
   คั่นด้วยช่องว่าง
2. เรียก `pop()` หนึ่งครั้ง แล้วพิมพ์ `descendants(0)` กับ
   `is_leaf(size() - 1)`

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน **ชุดคำสั่ง** และ
ถาม `descendants()` เป็นแสน ๆ ครั้งต่อบล็อก สลับกับ `push`, `pop`, `top`,
`size`, `is_leaf`, การคัดลอกฮีป และดัชนีที่เกินขอบเขต (ซึ่งต้องโยน
exception) ทั้งบนฮีปแบบ `std::less`, แบบ `std::greater` (min-heap) และบน
ฮีปของ struct ที่ไม่มี `operator<`

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
6
30 10 50 20 40 50
```

### ข้อมูลออก

```sample-output
5 2 1 0 0 0
4 1
```

ฮีปมีสมาชิก 6 ตัว ดังนั้นรากที่ดัชนี `0` มีลูกหลาน `5` ตัว ปุ่มที่ดัชนี `1`
มีลูกสองตัวคือดัชนี `3` และ `4` จึงได้ `2` ปุ่มที่ดัชนี `2` มีลูกเพียงตัวเดียว
คือดัชนี `5` จึงได้ `1` และดัชนี `3`, `4`, `5` เป็นใบ หลัง `pop()` เหลือ
สมาชิก 5 ตัว รากจึงมีลูกหลาน `4` ตัว และช่องสุดท้ายยังเป็นใบ

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `desc i` | พิมพ์ `descendants(i)` ของช่องที่มีอยู่จริง |
| `desc_raw i` | พิมพ์ `descendants(i)` โดยไม่ลดค่า `i` ซึ่งส่วนใหญ่เกินขอบเขตและต้องโยน `std::out_of_range` |
| `burst` | ถาม `descendants()` เป็นแสนครั้งด้วยดัชนีที่ grader สุ่มเองจาก seed โดยดัชนีส่วนใหญ่อยู่ใกล้ราก แล้วพิมพ์ค่ารวมเพียงบรรทัดเดียว |
| `is_leaf i` | พิมพ์ `is_leaf(i)` |

คำสั่ง `burst` คือหัวใจของชุดข้อมูลใหญ่: มันกินข้อมูลเข้าเพียงบรรทัดเดียว
แต่ถามคำถามเป็นแสนครั้งบนฮีปที่มีสมาชิกถึงหนึ่งล้านตัว เมื่อหมดคำสั่งของบล็อก
หนึ่ง grader จะตรวจสมบัติของฮีปแล้วไล่นำสมาชิกออกตามลำดับความสำคัญ

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมีสมาชิกไม่เกิน
10⁶ ตัว และมีคำสั่งไม่เกิน 500 คำสั่ง (แต่คำสั่ง `burst` หนึ่งคำสั่งนับเป็น
คำถามได้ถึง 1.8 × 10⁵ ครั้ง) สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน 10⁶ และ
ชนิด `long long` ไม่เกิน 4 × 10⁹
