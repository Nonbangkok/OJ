# Priority Queue K-th

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัว ปุ่มที่
ดัชนี `i` มีลูกอยู่ที่ดัชนี $2i + 1$ และ $2i + 2$ ลำดับความสำคัญตัดสินด้วย
`Comp mLess` โดย `mLess(a, b)` เป็นจริงเมื่อ `a` <b>สำคัญน้อยกว่า</b> `b` และ
สมบัติของฮีปคือทุกปุ่มสำคัญไม่น้อยกว่าลูกของมัน โปรแกรมตรวจใช้ทั้ง min-heap
และฮีปของ struct ที่ไม่มี `operator<` การเปรียบเทียบทุกจุดจึงต้องผ่าน `mLess`

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
T CP::priority_queue<T, Comp>::kth(size_t k) const;
```

ที่คืนสมาชิกที่ <b>สำคัญเป็นอันดับที่ `k`</b> ของฮีป (นับจาก `1` ดังนั้น
`kth(1)` คือค่าเดียวกับ `top()` และ `kth(k)` คือค่าที่ได้จากการเรียก `pop()`
ครั้งที่ `k`) ถ้า `k == 0` หรือ `k > mSize` ให้
`throw std::out_of_range("index out of range")`

เงื่อนไขที่ทำให้ข้อนี้ยาก

1. ต้องใช้เวลา <b>$O(k \log k)$</b> ต่อหนึ่งคำถาม ซึ่ง <b>ไม่ขึ้นกับ `mSize`</b> เลย
   ชุดข้อมูลใหญ่มีสมาชิกถึง $450{,}000$ ตัว แต่ถามด้วย `k` เพียงไม่กี่ร้อย และ
   ถามหลายพันครั้ง วิธีที่แตะทั้งอาเรย์ต่อหนึ่งคำถาม เช่น คัดลอกแล้วเรียง
   ($O(n \log n)$) หรือคัดลอกฮีปแล้ว `pop()` ซ้ำ `k` ครั้ง ($O(n + k \log n)$)
   ได้เพียง 50%
2. <b>ฮีปต้องไม่เปลี่ยน</b> `kth` เป็น `const` และโปรแกรมตรวจใช้ฮีปต่อหลังถาม
   ทุกครั้ง

แนวคิดที่ได้ $O(k \log k)$ คือ <b>ขยายกลุ่มผู้ท้าชิงทีละชั้นแทนการเรียงทั้งฮีป</b>

เริ่มจากกลุ่มผู้ท้าชิงที่มีดัชนี `0` เพียงตัวเดียว แล้วทำ `k` รอบ: ในแต่ละ
รอบ ให้หยิบดัชนีที่สมาชิกสำคัญที่สุดออกจากกลุ่ม แล้วนำ <b>ลูกทั้งสองของมัน</b>
เข้ากลุ่มแทน สมาชิกที่ถูกหยิบในรอบที่ `k` คือคำตอบ

เหตุผลที่ถูกต้อง: บรรพบุรุษของสมาชิกตัวใดก็สำคัญไม่น้อยกว่าตัวนั้น ดังนั้น
สมาชิกอันดับที่ `k` จะถูกหยิบหลังบรรพบุรุษของมันทั้งหมด และมันจะเข้ากลุ่ม
ผู้ท้าชิงทันทีที่พ่อของมันถูกหยิบ แต่ละรอบเพิ่มสมาชิกในกลุ่มได้ไม่เกินหนึ่งตัว
(หยิบออกหนึ่ง ใส่เข้าสอง) กลุ่มจึงมีขนาดไม่เกิน $k + 1$ ตลอด

หัวใจของการทำให้แต่ละรอบเป็น $O(\log k)$ คือ <b>กลุ่มผู้ท้าชิงต้องเป็นฮีปของ
ดัชนี</b> ซึ่งเรียงตามความสำคัญของ `mData[ดัชนี]` นั่นคือเทียบด้วย
`mLess(mData[a], mData[b])` คุณต้องเขียน fixUp/fixDown ของฮีปก้อนนี้เองในฟังก์ชัน
เพราะ `fixUp`/`fixDown` ของคลาสทำงานกับ `mData` ไม่ใช่กับกลุ่มผู้ท้าชิง

<b>ข้อยกเว้นของข้อบังคับข้อ 6 เฉพาะข้อนี้:</b> คุณจองอาเรย์ชั่วคราวในฟังก์ชันได้
ด้วย `new` / `delete` (เช่น `size_t *candidate = new size_t[2 * k + 2];`) โดย
ต้องคืนหน่วยความจำก่อนออกจากฟังก์ชัน และยังห้ามใช้โครงสร้างข้อมูลจาก standard
library หรือเพิ่มตัวแปรสมาชิกใหม่ให้คลาสเหมือนเดิม

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นอ่านจำนวนคำถาม `q` และค่า `k` ของแต่ละคำถาม แล้ว

1. บรรทัดแรก: ค่าที่ `kth(k)` คืนของทุกคำถาม คั่นด้วยช่องว่าง
2. บรรทัดที่สอง: `heap_ok()` และ `size()` ซึ่งต้องยืนยันว่าฮีปไม่เปลี่ยนเลย

`heap_ok()` เป็นฟังก์ชันที่เขียนไว้ให้แล้วใน `{{ds}}` ซึ่งตรวจว่าอาเรย์ยังมี
สมบัติของฮีปอยู่หรือไม่

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงฮีป<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป<br>
บรรทัดที่สาม : รับจำนวนเต็ม $q$ แทนจำนวนคำถาม<br>
บรรทัดที่สี่ : รับจำนวนเต็ม $q$ จำนวน คือ $k_1, k_2, \ldots, k_q$ แทนค่า $k$ ของแต่ละคำถาม

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ `kth(k)` คืนของทุกคำถาม คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่า `heap_ok()` และ `size()` คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
6
30 10 50 20 40 50
3
1 3 6
```

### ข้อมูลออก

```sample-output
50 40 10
1 6
```

## คำอธิบายตัวอย่างที่ 1

ฮีปเก็บ `{30, 10, 50, 20, 40, 50}` เรียงตามความสำคัญได้
`50 50 40 30 20 10` ดังนั้น `kth(1)` คือ `50`, `kth(3)` คือ `40` และ
`kth(6)` คือ `10` (สังเกตว่า `kth(2)` ก็คือ `50` เพราะมีค่า `50` สองตัว)
หลังถามทั้งสามครั้ง ฮีปยังมีสมาชิก `6` ตัวและยังเป็นฮีปที่ถูกต้อง

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `kth k` | พิมพ์ `kth(k)` โดย `k` อยู่ในช่วงที่ถูกต้อง (บางคำถามใช้ `k` ถึงหลักแสน) |
| `kth_raw k` | พิมพ์ `kth(k)` โดยไม่ปรับค่า `k` ซึ่งรวมถึง `k = 0` และค่าที่เกิน `mSize` และต้องโยน `std::out_of_range` |
| `burst` | ถาม `kth()` หลายพันครั้งด้วย `k` ที่ grader สุ่มเองจาก seed แล้วพิมพ์ค่ารวม, จำนวนสมาชิก, ผลของ `heap_ok()` และ `top()` |

คำสั่ง `burst` คือหัวใจของชุดข้อมูลใหญ่: มันกินข้อมูลเข้าเพียงบรรทัดเดียว
แต่ถามคำถามหลายพันครั้งบนฮีปที่มีสมาชิกหลายแสนตัว ด้วย `k` เพียงไม่กี่ร้อย
และยังตรวจว่าฮีปไม่ถูกแก้หลังการถามด้วย เมื่อหมดคำสั่งของบล็อกหนึ่ง grader
จะไล่นำสมาชิกออกจากฮีปตามลำดับความสำคัญเพื่อตรวจทั้งก้อนอีกครั้ง

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกไม่เกิน $n \leq 450{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 160$ คำสั่ง แต่คำสั่ง `burst` หนึ่งคำสั่งนับเป็นคำถามได้ถึง $2{,}800$ ครั้ง
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
