# Queue At

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย <b>ring buffer</b> นั่นคือ
อาเรย์ `mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่
ที่ `mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม เมื่อเดินเลยช่องสุดท้ายของ
อาเรย์แล้วจะวนกลับมาที่ช่องที่ $0$ คลาสนี้ยังมีตัวแปรสมาชิก `int aux` ซึ่งข้อนี้
ไม่จำเป็นต้องใช้

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
const T &CP::queue<T>::at(size_t i) const;
```

ที่คืนค่าอ้างอิงของ <b>สมาชิกลำดับที่ `i` นับจากหน้าสุด</b> โดยนับเริ่มจาก $0$
ดังนั้น `at(0)` คือสมาชิกตัวเดียวกับที่ `front()` คืนให้ และ `at(size() - 1)`
คือตัวเดียวกับที่ `back()` คืนให้ รับประกันว่าทุกครั้งที่เรียก `at` จะมี
$0 \leq i < \text{size()}$ เสมอ

ข้อควรระวังอยู่ที่การวนรอบ ตำแหน่งทางกายภาพของสมาชิกลำดับที่ `i` <b>ไม่ใช่</b>
`mFront + i` เพราะเมื่อ `mFront + i` เลยปลายอาเรย์ไปแล้วต้องวนกลับมาที่ต้น
อาเรย์ คิวที่ผ่านการ `push` และ `pop` สลับกันหลายครั้งจะอยู่ในสภาพวนรอบแบบนี้
เกือบตลอดเวลา ไม่ใช่สภาพที่ `mFront` เป็น $0$ เหมือนตอนเพิ่งสร้างคิว

ฟังก์ชันที่ `at` ต้องให้ผลสอดคล้องกัน คือ `front`, `back`, `push` และ `pop`
เขียนไว้ให้เรียบร้อยแล้วในไฟล์ `{{ds}}` คุณไม่ต้องแก้และแก้ไม่ได้ ไฟล์
`{{submission}}` จึงมีเพียงฟังก์ชัน `at` ที่ยังว่างอยู่ให้คุณเติม

ฟังก์ชันนี้ต้องทำงานในเวลา <b>$O(1)$</b> ต่อการเรียกหนึ่งครั้ง คือคำนวณตำแหน่ง
ด้วยการหารเอาเศษครั้งเดียว ไม่ใช่เดินทีละช่องจาก `mFront` ไปจนครบ `i` ช่อง ใน
ชุดทดสอบ 30% สุดท้ายคิวยาวหลายหมื่นตัวและ grader มีคำสั่งที่ไล่อ่านทุกตำแหน่ง
ของคิว วิธีที่เดินทีละช่องใช้เวลา $O(i)$ ต่อการเรียกหนึ่งครั้ง และจะได้ Time
Limit Exceeded

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
คิวตามลำดับ จากนั้นอ่านจำนวนคำถาม $m$ และดัชนี $m$ ตัว แล้วพิมพ์ค่าของ `at(i)`
ของทุกดัชนีที่อ่านมา จากนั้น `pop()` หนึ่งครั้งและ `push(60)` หนึ่งครั้ง แล้ว
พิมพ์ `at(0)`, `at(size() - 1)` และ `size()` ส่วนหลังนี้มีไว้เพื่อให้เห็นว่า
`at` ต้องยังถูกต้องหลังจาก `mFront` ขยับแล้ว

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `at` สลับกับ `push`, `pop`, `front`, `back`
  และ `size` หลายครั้ง ไม่ใช่เรียกเรียงกันเป็นชุดเดียวตอนท้าย
* จงใจ `pop` แล้ว `push` ซ้ำ ๆ จนคิวอยู่ในสภาพวนรอบ แล้วจึงถาม `at` ด้วย
  ดัชนีที่ตำแหน่งทางกายภาพอยู่เลยปลายอาเรย์ไปแล้ว
* สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด คือ `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
* คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงคิว<br>
บรรทัดที่สาม : รับจำนวนเต็ม $m$ แทนจำนวนคำถาม<br>
บรรทัดที่สี่ : รับจำนวนเต็ม $m$ จำนวน คือดัชนี $i_1, i_2, \ldots, i_m$ ที่จะถาม
ด้วย `at`

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าของ `at(i)` ของทุกดัชนีที่อ่านมา คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าของ `at(0)`, `at(size() - 1)` และ `size()` หลังเรียก
`pop()` หนึ่งครั้งและ `push(60)` หนึ่งครั้ง คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
5
10 20 30 40 50
3
0 2 4
```

```sample-output
10 30 50
20 60 5
```

## คำอธิบายตัวอย่างที่ 1

คิวเริ่มต้นเป็น $10, 20, 30, 40, 50$ ทำให้ `at(0)`, `at(2)` และ `at(4)` เป็น
$10$, $30$ และ $50$ ตามลำดับ หลังจาก `pop()` และ `push(60)` คิวกลายเป็น
$20, 30, 40, 50, 60$ จึงได้ `at(0)` เป็น $20$, `at(4)` เป็น $60$ และ `size()`
เป็น $5$

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
คิวว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` เข้าท้ายคิว |
| `pop` | นำสมาชิกตัวหน้าสุดออก (ถ้าคิวว่างจะข้ามคำสั่งนี้) |
| `front` | พิมพ์สมาชิกตัวหน้าสุด |
| `back` | พิมพ์สมาชิกตัวหลังสุด |
| `at i` | พิมพ์ `at(i)` |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกคิว แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |
| `digest` | พิมพ์ค่าสรุปที่คำนวณจาก `at(0)` ถึง `at(size() - 1)` ทุกตัว |

คำสั่ง `digest` เป็นการไล่อ่านคิวทั้งคิวผ่าน `at` แล้วย่อผลลัพธ์เป็นเลขตัว
เดียว ถ้ามีสมาชิกตัวใดตัวหนึ่งผิดตำแหน่ง ค่านี้จะเปลี่ยนไปทันที

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งหมดด้วย
`front` และ `pop` แล้วพิมพ์จำนวนสมาชิกพร้อมค่าสรุปของลำดับที่ได้ จึงเป็นการ
ตรวจทั้งคิว ไม่ใช่แค่หัวและท้าย

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้น $n \leq 50{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $130{,}000$ คำสั่ง
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $10^6$ สำหรับ `int` และไม่เกิน
  $4 \times 10^9$ สำหรับ `long long`
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
