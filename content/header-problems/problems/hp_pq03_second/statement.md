## คำอธิบาย

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
**ไบนารีฮีป** (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัว ปุ่มที่
ดัชนี `i` มีลูกอยู่ที่ดัชนี `2i + 1` และ `2i + 2` ลำดับความสำคัญตัดสินด้วย
อ็อบเจกต์เปรียบเทียบ `Comp mLess` โดย `mLess(a, b)` เป็นจริงเมื่อ `a`
**สำคัญน้อยกว่า** `b` และฮีปรักษาเงื่อนไขว่าทุกปุ่มสำคัญไม่น้อยกว่าลูกของมัน
สมาชิกที่สำคัญที่สุดจึงอยู่ที่ `mData[0]` เสมอ

`Comp` เปลี่ยนความหมายของคำว่า "สำคัญ" ได้ทั้งหมด เช่น
`CP::priority_queue<int, std::greater<int>>` เป็น min-heap และโปรแกรมตรวจยัง
ใช้ฮีปของ struct ที่ **ไม่มี `operator<`** ดังนั้นการเปรียบเทียบทุกจุดใน
คำตอบของคุณต้องผ่าน `mLess` เท่านั้น

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
T CP::priority_queue<T, Comp>::second() const;
```

ที่คืนสมาชิกที่ **สำคัญเป็นอันดับสอง** ของฮีป (ถ้ามีสมาชิกที่สำคัญเท่ากัน
หลายตัว ตัวที่สำคัญเป็นอันดับสองคือตัวที่ได้จากการเรียก `pop()` ครั้งที่สอง)
ถ้าฮีปมีสมาชิกน้อยกว่าสองตัว ให้
`throw std::out_of_range("index out of range")`

ต้องทำใน **O(1)** คือห้ามไล่ดูทุกตัว เหตุผลที่ทำได้คือ **สมาชิกที่สำคัญเป็น
อันดับสองต้องเป็นลูกของราก** เสมอ ถ้ามันอยู่ลึกกว่านั้น พ่อของมันซึ่งไม่ใช่ราก
จะสำคัญไม่น้อยกว่ามัน และจะกลายเป็นอันดับสองแทน ดังนั้นผู้ท้าชิงมีแค่ดัชนี
`1` กับ `2` เท่านั้น (ระวังกรณี `mSize == 2` ที่ดัชนี `2` ยังไม่มีสมาชิก)

ไฟล์ `{{ds}}` ยังมีฟังก์ชัน `take_two()` ที่เขียนไว้ให้แล้วบน `second()` ของคุณ
ซึ่งนำสมาชิกสองตัวที่สำคัญที่สุดออกจากฮีปแล้วคืนตัวที่เป็นอันดับสอง ถ้า
`second()` เลือกผิดตัว ค่าที่ฟังก์ชันนี้คืนก็จะผิดตามไปด้วย

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: `top()` และ `second()` คั่นด้วยช่องว่าง
2. บรรทัดที่สอง: ค่าที่ `take_two()` คืน และ `size()` ที่เหลืออยู่
3. บรรทัดที่สาม: `top()` และ `second()` ของฮีปที่เหลือ

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน **ชุดคำสั่ง** และ
เรียก `second()` สลับกับ `push`, `pop`, `top`, `size`, `take_two` และการคัดลอก
ฮีป เป็นหลักหมื่นครั้งต่อหนึ่งชุดทดสอบ

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
6
30 10 50 20 40 50
```

### ข้อมูลออก

```sample-output
50 50
50 4
40 30
```

ฮีปเก็บ `{30, 10, 50, 20, 40, 50}` มีค่า `50` สองตัว ดังนั้นทั้ง `top()` และ
`second()` คืน `50` จากนั้น `take_two()` นำ `50` ทั้งสองตัวออก คืนค่า `50`
และเหลือสมาชิก `4` ตัว ฮีปที่เหลือคือ `{30, 10, 20, 40}` จึงได้ `top()` คืน
`40` และ `second()` คืน `30`

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `second` | พิมพ์ค่าที่ `second()` คืน (ถ้ามีสมาชิกน้อยกว่าสองตัว ต้องโยน `std::out_of_range`) |
| `take_two` | พิมพ์ค่าที่ `take_two()` คืน ซึ่งนำสองตัวที่สำคัญที่สุดออกจากฮีป |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะตรวจสมบัติของฮีปอีกครั้งแล้วไล่นำสมาชิก
ออกตามลำดับความสำคัญ จึงเป็นการตรวจทั้งฮีป ไม่ใช่แค่ค่าที่พิมพ์ไป

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมีสมาชิกไม่เกิน
120,000 ตัว และมีคำสั่งไม่เกิน 16,000 คำสั่ง สมาชิกชนิด `int` มีค่าสัมบูรณ์
ไม่เกิน 10⁶ และชนิด `long long` ไม่เกิน 4 × 10⁹
