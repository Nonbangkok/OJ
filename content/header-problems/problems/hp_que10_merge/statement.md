# Queue Merge

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย <b>ring buffer</b> นั่นคือ
อาเรย์ `mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่
ที่ `mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม เมื่อเดินเลยช่องสุดท้ายของ
อาเรย์แล้วจะวนกลับมาที่ช่องที่ $0$ คลาสนี้ยังมีตัวแปรสมาชิก `int aux` ซึ่งข้อนี้
ไม่จำเป็นต้องใช้

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::queue<T>::merge(CP::queue<T> &other);
```

ที่ย้ายสมาชิกทั้งหมดของ `other` มาต่อ <b>ท้ายคิวนี้</b> โดยคงลำดับเดิมของทั้งสอง
คิว แล้วทำให้ `other` กลายเป็นคิวว่าง หลังเรียกฟังก์ชันนี้

* `size()` ของคิวนี้ต้องเท่ากับผลรวมของขนาดเดิมทั้งสองคิว
* `other.size()` ต้องเป็น $0$ และ `other` ต้องยังใช้งานต่อได้ตามปกติ คือ
  `push` ของใหม่เข้าไปแล้วทำงานถูกต้อง
* ถ้า `other` ว่างอยู่แล้ว ต้องไม่มีอะไรเปลี่ยน

ตัวอย่างเช่น คิวนี้เป็น `A B C` และ `other` เป็น `D E` หลัง `merge(other)`
คิวนี้จะเป็น `A B C D E` และ `other` ว่าง

ข้อสำคัญคือ <b>เวลาที่ใช้</b> ให้ $n$ เป็นขนาดของคิวนี้และ $m$ เป็นขนาดของ
`other` ฟังก์ชันนี้ต้องใช้เวลา <b>$O(n + m)$</b> ต่อการเรียกหนึ่งครั้ง

เนื่องจาก `merge` เป็นฟังก์ชันสมาชิกของคลาสเดียวกัน คุณเข้าถึงตัวแปรภายใน
ของ `other` ได้โดยตรง เช่น `other.mData`, `other.mSize`, `other.mFront` และ
`other.mCap` ดังนั้นไม่ต้องเรียก `push` ทีละตัว คัดลอกจากอาเรย์หนึ่งไปอีก
อาเรย์หนึ่งได้เลย โดยมีสามจุดที่ต้องระวัง

1. <b>ต้องจองที่เผื่อไว้ให้พอในครั้งเดียว</b> ด้วย
   `ensureCapacity(mSize + other.mSize)` ก่อนเริ่มคัดลอก การขยายอาเรย์ทีละช่อง
   หรือทีละตัวที่คัดลอกทำให้ต้องย้ายข้อมูลทั้งคิวซ้ำ ๆ กลายเป็น
   $O((n + m) \times m)$ และจะได้ Time Limit Exceeded ในชุดทดสอบ 50% หลัง
2. `ensureCapacity` อาจเรียก `expand` ซึ่งย้ายข้อมูลไปเริ่มที่ช่อง $0$ และ
   เปลี่ยนทั้ง `mFront` และ `mCap` ดังนั้นตำแหน่งปลายทางต้องคำนวณ <b>หลัง</b>
   เรียก `ensureCapacity` เสมอ
3. ทั้งคิวต้นทางและคิวปลายทางอาจพาดข้ามปลายอาเรย์ของตัวเอง และทั้งสองคิวมี
   `mCap` ไม่เท่ากัน การวนรอบของฝั่งต้นทางจึงต้องใช้ `% other.mCap` ส่วนฝั่ง
   ปลายทางใช้ `% mCap` ผู้ออกข้อสอบจงใจให้ทั้งสองฝั่งอยู่ในสภาพพาดข้ามปลาย
   อาเรย์ตอนเรียก `merge`

ไม่ต้องรองรับกรณี `merge` กับตัวเอง (`q.merge(q)`) ระบบตรวจไม่ทดสอบกรณีนี้

ฟังก์ชัน `front`, `back`, `push` และ `pop` เขียนไว้ให้เรียบร้อยแล้วในไฟล์
`{{ds}}` คุณไม่ต้องแก้และแก้ไม่ได้ ไฟล์ `{{submission}}` จึงมีเพียงฟังก์ชัน
`merge` ที่ยังว่างอยู่ให้คุณเติม

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ และสมาชิก $n$ ตัวมา `push` ลงคิว
`a` แล้วอ่านจำนวน $m$ และสมาชิก $m$ ตัวมา `push` ลงคิว `b` จากนั้นเรียก
`a.merge(b)` แล้วพิมพ์ `a.size()` และ `b.size()` จากนั้น `b.push(99)` แล้วพิมพ์
`b.front()`, `b.back()` และ `b.size()` ซึ่งแสดงว่าคิวที่ถูกเททิ้งแล้วยังใช้งานได้
ตามด้วยสมาชิกทั้งหมดของ `a`

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* ถือคิวสองคิวต่อหนึ่งบล็อก และอ่าน <b>ชุดคำสั่ง</b> ที่ระบุว่าคำสั่งนั้นทำกับ
  คิวใด โดยเรียก `merge` สลับกับ `push`, `pop`, `front`, `back` และ `size`
  หลายครั้ง และสั่ง merge ทั้งสองทิศทาง
* จงใจ `pop` แล้ว `push` ซ้ำ ๆ ให้ทั้งสองคิวพาดข้ามปลายอาเรย์ของตัวเองก่อน
  สั่ง merge และจัดขนาดให้ช่วงที่ต้องเขียนลงคิวปลายทางพาดข้ามปลายอาเรย์ด้วย
* สั่ง merge ตอนที่คิวต้นทางว่าง และตอนที่คิวปลายทางว่าง
* `push` ของใหม่ลงคิวที่เพิ่งถูกเททิ้ง แล้วตรวจลำดับของมันอีกครั้ง
* สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด คือ `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
* คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว `a`<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงคิว `a`<br>
บรรทัดที่สาม : รับจำนวนเต็ม $m$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว `b`<br>
บรรทัดที่สี่ : รับจำนวนเต็ม $m$ จำนวน คือ $b_1, b_2, \ldots, b_m$ ตามลำดับที่
`push` ลงคิว `b`

## Output :

มีทั้งหมด $3$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าของ `a.size()` และ `b.size()` หลังเรียก `a.merge(b)`
คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าของ `b.front()`, `b.back()` และ `b.size()` หลังจาก
`b.push(99)` คั่นด้วยช่องว่าง<br>
บรรทัดที่สาม : แสดงสมาชิกทั้งหมดของ `a` โดยวนพิมพ์ `a.front()` แล้ว `a.pop()`
จนคิวว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
3
1 2 3
2
7 8
```

```sample-output
5 0
99 99 1
1 2 3 7 8
```

## คำอธิบายตัวอย่างที่ 1

คิว `a` เป็น $1, 2, 3$ และคิว `b` เป็น $7, 8$ หลัง `a.merge(b)` คิว `a` เป็น
$1, 2, 3, 7, 8$ (ขนาด $5$) และคิว `b` ว่าง (ขนาด $0$) จากนั้น `b.push(99)`
ทำให้ `b` มีสมาชิกตัวเดียวคือ $99$ ซึ่งเป็นทั้งตัวหน้าสุดและตัวหลังสุด

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกมีคิวสอง
คิวคือคิวหมายเลข $0$ และ $1$ เริ่มจากว่างทั้งคู่และใช้ชนิดข้อมูลเดียวกัน ทุก
คำสั่งระบุหมายเลขคิว `s` ที่จะทำด้วย

| คำสั่ง | ความหมาย |
|---|---|
| `push s x` | ใส่ `x` เข้าท้ายคิว `s` |
| `pop s` | นำสมาชิกตัวหน้าสุดของคิว `s` ออก (ถ้าว่างจะข้ามคำสั่งนี้) |
| `merge s` | เรียก `queue[s].merge(queue[1 - s])` แล้วพิมพ์ขนาดของคิวทั้งสอง |
| `front s` | พิมพ์สมาชิกตัวหน้าสุดของคิว `s` |
| `back s` | พิมพ์สมาชิกตัวหลังสุดของคิว `s` |
| `size s` | พิมพ์จำนวนสมาชิกของคิว `s` |
| `copy s` | คัดลอกคิว `s` แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |
| `digest s` | พิมพ์ค่าสรุปที่คำนวณจากสมาชิกทุกตัวของคิว `s` เรียงจากหน้าไปหลัง |

คำสั่ง `digest` ทำงานบนสำเนาของคิว โดยอ่าน `front()` แล้ว `pop()` ไปเรื่อย ๆ
จนหมดคิว แล้วย่อลำดับทั้งหมดเป็นเลขตัวเดียว การ merge ที่สลับลำดับ ทำสมาชิก
หายไป หรือคัดลอกซ้ำ จะเปลี่ยนค่านี้ทันที

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งสองคิวด้วย
`front` และ `pop` แล้วพิมพ์จำนวนสมาชิกพร้อมค่าสรุปของลำดับที่ได้ของแต่ละคิว

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $2$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้นคิวละไม่เกิน $26{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $30{,}000$ คำสั่ง
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $10^6$ สำหรับ `int` และไม่เกิน
  $4 \times 10^9$ สำหรับ `long long`
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
