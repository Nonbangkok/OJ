# Priority Queue Rank

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิก `mSize` ตัวที่ดัชนี
`0` ถึง `mSize - 1` ลำดับความสำคัญตัดสินด้วยอ็อบเจกต์เปรียบเทียบ
`Comp mLess` โดย `mLess(a, b)` เป็นจริงเมื่อ `a` <b>สำคัญน้อยกว่า</b> `b`

`Comp` เปลี่ยนความหมายของคำว่า "สำคัญ" ได้ทั้งหมด เช่น
`CP::priority_queue<int, std::greater<int>>` เป็น min-heap ที่เลขน้อยสำคัญกว่า
และโปรแกรมตรวจยังใช้ฮีปของ struct ที่ <b>ไม่มี `operator<`</b> ดังนั้นการ
เปรียบเทียบทุกจุดในคำตอบของคุณต้องผ่าน `mLess` เท่านั้น

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
size_t CP::priority_queue<T, Comp>::rank(size_t i) const;
```

ที่คืนจำนวนสมาชิกในฮีปที่ <b>สำคัญกว่า</b> `mData[i]` โดยนับเฉพาะตัวที่สำคัญกว่า
อย่างเคร่งครัด ถ้า $i \geq$ `mSize` ให้
`throw std::out_of_range("index out of range")`

สองจุดที่พลาดกันบ่อย

1. <b>นับเฉพาะตัวที่สำคัญกว่าอย่างเคร่งครัด</b> สมาชิกที่สำคัญ *เท่ากัน* กับ
   `mData[i]` ไม่ต้องนับ และ `mData[i]` เองก็ไม่ต้องนับ เงื่อนไขที่ถูกต้องคือ
   `mLess(mData[i], mData[j])` ซึ่งไม่เท่ากับ `!mLess(mData[j], mData[i])`
2. <b>ลำดับของอาร์กิวเมนต์</b> `mLess(a, b)` หมายถึง `a` สำคัญน้อยกว่า `b` การ
   สลับที่กันทำให้ได้คำตอบตรงข้าม

ข้อนี้ไม่บังคับความเร็วเป็นพิเศษ: คำตอบอาจมีค่าได้ถึง `mSize - 1` ดังนั้นการ
ไล่ดูทุกสมาชิกหนึ่งรอบ (เวลา $O(n)$) ถือว่าผ่าน

ไฟล์ `{{ds}}` ยังมีฟังก์ชัน `is_top()` ที่เขียนไว้ให้แล้วเป็น `rank(i) == 0`
ดังนั้นถ้า `rank()` นับตัวที่สำคัญเท่ากันเข้าไปด้วย ฟังก์ชันนี้จะตอบว่า
สมาชิกที่สำคัญที่สุดไม่ใช่ตัวที่สำคัญที่สุด

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: `rank(i)` ของทุกช่อง `i` ตั้งแต่ `0` ถึง `size() - 1` คั่นด้วย
   ช่องว่าง (ค่าเหล่านี้ขึ้นกับการจัดเรียงภายในอาเรย์ของฮีป)
2. บรรทัดที่สอง: `top()` และ `is_top(0)`

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน <b>ชุดคำสั่ง</b> และ
เรียก `rank()` สลับกับ `push`, `pop`, `top`, `size`, `is_top` และการคัดลอกฮีป
ทั้งบนฮีปแบบ `std::less`, แบบ `std::greater` (min-heap) และบนฮีปของ struct ที่
ไม่มี `operator<` รวมถึงเรียกด้วยดัชนีที่เกินขอบเขตเพื่อตรวจว่าโยน exception
จริง

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงฮีป<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่า `rank(i)` ของทุกช่อง $i$ ตั้งแต่ $0$ ถึง $n - 1$ คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าที่ได้จาก `top()` และ `is_top(0)` คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
6
30 10 50 20 40 50
```

### ข้อมูลออก

```sample-output
0 2 0 5 4 3
50 1
```

## คำอธิบายตัวอย่างที่ 1

หลัง `push` ทั้งหกตัว อาเรย์ภายในเป็น `50 40 50 10 20 30` ช่องที่ `0` และ `2`
เก็บ `50` ซึ่งไม่มีใครสำคัญกว่า จึงได้ `rank` เป็น `0` ทั้งคู่ (สังเกตว่าทั้ง
สองตัวสำคัญเท่ากัน จึงไม่นับกันเอง) ส่วนช่องที่ `3` เก็บ `10` ซึ่งมีสมาชิก
สำคัญกว่าอยู่ `5` ตัว

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `rank i` | พิมพ์ `rank(i)` ของช่องที่มีอยู่จริง |
| `rank_raw i` | พิมพ์ `rank(i)` โดยไม่ลดค่า `i` ซึ่งส่วนใหญ่เกินขอบเขตและต้องโยน `std::out_of_range` |
| `is_top i` | พิมพ์ `is_top(i)` |

หลายบล็อกใช้ค่าจากช่วงที่แคบมาก ทำให้มีสมาชิกที่สำคัญเท่ากันจำนวนมาก และเมื่อ
หมดคำสั่งของบล็อกหนึ่ง grader จะตรวจสมบัติของฮีปแล้วไล่นำสมาชิกออกตามลำดับ
ความสำคัญ

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกไม่เกิน $n \leq 20{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 1{,}600$ คำสั่ง
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
