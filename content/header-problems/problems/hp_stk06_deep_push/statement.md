# Stack Deep Push

คลาส `CP::stack<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลไว้ในอาเรย์ `mData` ที่จองไว้
`mCap` ช่อง โดยใช้งานจริง `mSize` ช่องแรก และสมาชิกตัวบนสุดของสแตกอยู่ที่
`mData[mSize - 1]` ฟังก์ชัน `ensureCapacity` ที่คลาสมีให้จะขยายอาเรย์เมื่อที่
ไม่พอ (และคัดลอกข้อมูลเดิมไปยังอาเรย์ใหม่)

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::stack<T>::deep_push(size_t k, const T &element);
```

ที่ <b>แทรกสมาชิกใหม่ไว้ใต้สมาชิก $k$ ตัวบนสุด</b> นั่นคือหลังเรียกเสร็จต้องมี
สมาชิกอยู่เหนือตัวใหม่พอดี $k$ ตัว และลำดับของสมาชิกเดิมทั้งหมดต้องไม่
เปลี่ยน โดย

* $k = 0$ มีความหมายเท่ากับ `push(element)` คือวางไว้บนสุด
* $k \geq \text{size}()$ ให้ตัวใหม่ไปอยู่ล่างสุดของสแตก (ไม่ใช่ข้อผิดพลาด) ข้อมูล
  ทดสอบมี $k$ ที่ใหญ่กว่าจำนวนสมาชิกจริง รวมถึงค่าระดับพันล้าน
* ต้องใช้เวลา <b>$O(k)$</b> ไม่ใช่ $O(\text{size}())$ จึงต้องย้ายเฉพาะสมาชิกที่อยู่เหนือ
  ตำแหน่งแทรกเท่านั้น

กับดักสำคัญ : พารามิเตอร์ `element` เป็น <b>การอ้างอิง</b> ไม่ใช่สำเนา และ
โปรแกรมของผู้ออกข้อสอบมีคำสั่งที่เรียก `deep_push(k, top())` ซึ่งส่งการ
อ้างอิงไปยังสมาชิกของสแตกตัวเดียวกันเข้ามา ถ้าคุณเลื่อนข้อมูลหรือเรียก
`ensureCapacity` (ซึ่งอาจย้ายอาเรย์ทั้งก้อน) ก่อนที่จะสำเนาค่าออกมาเก็บไว้
ค่าที่ `element` ชี้อยู่จะถูกเขียนทับหรือถูกทำลายไปก่อน แล้วสิ่งที่แทรกลงไป
จะเป็นขยะ

โจทย์ข้อนี้ย้าย `top`, `push` และ `pop` มาไว้ใน `{{submission}}` ด้วย คุณจึง
แก้ได้ถ้าจำเป็น แต่ทั้งสามต้องยังทำงานถูกต้องตามความหมายเดิม เพราะโปรแกรม
ตรวจเรียกใช้งานสลับกับ `deep_push` ตลอด

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
สแตกตามลำดับ จากนั้นเรียก `deep_push(0, 100)`, `deep_push(2, 200)` และ
`deep_push(1000, 300)` แล้วพิมพ์จำนวนสมาชิกจาก `size()` ตามด้วยสมาชิกทั้งหมด
โดยวนพิมพ์ `top()` แล้ว `pop()` จนสแตกว่าง

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `deep_push` สลับกับ `push`, `pop`, `top`,
  `size` หลายครั้ง ดังนั้นถ้าคุณแก้ `push`, `pop` หรือ `top` แล้วทำให้
  พฤติกรรมเดิมเสียไป ระบบจะจับได้
* เรียก `deep_push(k, top())` เพื่อทดสอบกรณีการอ้างอิงที่กล่าวไว้ข้างต้น
* สร้างสแตกจากชนิดข้อมูลมากกว่าหนึ่งชนิด เช่น `CP::stack<int>`,
  `CP::stack<std::string>` และ `CP::stack<long long>`
* คัดลอกสแตกด้วย copy constructor และ copy assignment แล้วตรวจว่าสแตกต้นฉบับ
  ไม่เปลี่ยน

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงสแตก<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงสแตก

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงจำนวนสมาชิกจาก `size()` หลังเรียก `deep_push` ทั้งสามครั้ง<br>
บรรทัดที่สอง : แสดงสมาชิกทั้งหมด โดยวนพิมพ์ `top()` แล้ว `pop()` จนสแตกว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
5
10 20 30 40 50
```

```sample-output
8
100 50 200 40 30 20 10 300
```

## คำอธิบายตัวอย่างที่ 1

เริ่มจากสแตก (ล่าง → บน) $10, 20, 30, 40, 50$

* `deep_push(0, 100)` วาง $100$ ไว้บนสุด ได้ $10, 20, 30, 40, 50, 100$
* `deep_push(2, 200)` แทรก $200$ ใต้สองตัวบนสุด ($50$ และ $100$) ได้
  $10, 20, 30, 40, 200, 50, 100$
* `deep_push(1000, 300)` ลึกกว่าจำนวนสมาชิก จึงไปอยู่ล่างสุด ได้
  $300, 10, 20, 30, 40, 200, 50, 100$

เมื่อพิมพ์จากบนลงล่างจึงได้ $100, 50, 200, 40, 30, 20, 10, 300$ และมีสมาชิก
$8$ ตัว

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
สแตกว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงบนสแตก |
| `pop` | นำสมาชิกตัวบนสุดออก (ถ้าสแตกว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกตัวบนสุด หรือ `-` ถ้าสแตกว่าง |
| `size` | พิมพ์จำนวนสมาชิก |
| `deep k x` | เรียก `deep_push(k, x)` |
| `copy` | คัดลอกสแตก แล้วพิมพ์ข้อมูลของสำเนา โดยสแตกต้นฉบับต้องไม่เปลี่ยน |
| `fold` | เรียก `top()` แล้วนำค่าไปรวมใน hash ของบล็อก (ไม่พิมพ์อะไร) |
| `self k` | เรียก `deep_push(k, top())` (ข้ามคำสั่งนี้ถ้าสแตกว่าง) |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากสแตกทั้งหมด แล้ว
พิมพ์สมาชิก $100$ ตัวแรกที่นำออก ตามด้วยค่า hash ของสมาชิกทุกตัวที่เคยถูกอ่าน
การตรวจความลึกที่แทรกจึงอาศัยลำดับทั้งสแตก ไม่ใช่แค่ตัวบนสุด

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกเริ่มต้น $n \leq 30{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 90{,}000$ คำสั่ง
* ค่า $k$ ไม่เกิน $4 \times 10^9$ และผลรวมของ $\min(k, \text{size}())$ ทุกคำสั่งไม่เกิน $2 \times 10^7$
* สมาชิกชนิดจำนวนเต็มมีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
* สมาชิกชนิดข้อความเป็นตัวอักษรภาษาอังกฤษตัวเล็กยาวไม่เกิน $6$ ตัว
