## คำอธิบาย

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
**ไบนารีฮีป** (binary heap) บนอาเรย์ `mData` ซึ่งมีสมาชิกจริง `mSize` ตัวที่
ดัชนี `0` ถึง `mSize - 1` ปุ่มที่ดัชนี `i` มีลูกอยู่ที่ดัชนี `2i + 1` และ
`2i + 2` และปุ่มที่ดัชนี `c` (เมื่อ `c ≥ 1`) มีพ่ออยู่ที่ดัชนี `(c - 1) / 2`

ลำดับความสำคัญไม่ได้ตัดสินด้วย `operator<` แต่ตัดสินด้วยอ็อบเจกต์เปรียบเทียบ
`Comp mLess` โดย `mLess(a, b)` เป็นจริงเมื่อ `a` **สำคัญน้อยกว่า** `b` และ
**สมบัติของฮีป** (heap property) คือ

> ทุกปุ่มต้องสำคัญ **ไม่น้อยกว่า** ลูกทุกตัวของมัน

เขียนด้วย `mLess` ได้ว่า สำหรับทุกคู่พ่อลูก `(p, c)` ต้องได้
`mLess(mData[p], mData[c])` เป็นเท็จ สังเกตว่าถ้าพ่อกับลูกสำคัญเท่ากัน
สมบัติของฮีปยังถือว่าเป็นจริง

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
bool CP::priority_queue<T, Comp>::is_heap() const;
```

ที่คืน `true` เมื่ออาเรย์ `mData[0..mSize-1]` มีสมบัติของฮีปครบทุกคู่พ่อลูก
และคืน `false` เมื่อมีคู่ใดคู่หนึ่งผิด ฮีปว่างและฮีปที่มีสมาชิกตัวเดียวถือว่า
มีสมบัติของฮีป

คำใบ้: วนตามดัชนี **ลูก** `c = 1, 2, ..., mSize - 1` แล้วเทียบกับพ่อ
`(c - 1) / 2` จะเจอทุกคู่พ่อลูกครบพอดีคู่ละครั้ง ซึ่งง่ายกว่าวนตามดัชนีพ่อแล้ว
ไปดูลูกสองตัว เพราะไม่ต้องกังวลเรื่องปุ่มที่มีลูกตัวเดียวหรือลูกเกินขอบอาเรย์

ปกติฮีปที่สร้างด้วย `push` และ `pop` จะมีสมบัติของฮีปอยู่แล้ว ไฟล์ `{{ds}}` จึง
มีฟังก์ชัน `raw_push()` และ `raw_swap()` เตรียมไว้ให้โปรแกรมตรวจใช้ **ทำลาย**
อาเรย์ได้: `raw_push()` ต่อสมาชิกท้ายอาเรย์โดยไม่เรียก `fixUp` และ
`raw_swap()` สลับสองช่องโดยไม่ซ่อมอะไร คุณไม่ต้องเรียกสองฟังก์ชันนี้เอง

## คำอธิบายฟังก์ชัน main

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: ค่าที่ได้จาก `is_heap()` ซึ่งต้องเป็น `1`
2. เรียก `raw_swap(0, n - 1)` เพื่อสลับรากกับช่องสุดท้าย แล้วพิมพ์
   `is_heap()` กับ `top()` คั่นด้วยช่องว่าง

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน **ชุดคำสั่ง** และ
สลับกันระหว่างการสร้างฮีปที่ถูกต้องด้วย `push`/`pop` กับการทำลายอาเรย์ด้วย
`raw_push`/`raw_swap` แล้วถาม `is_heap()` หลายพันครั้ง ทั้งบนฮีปแบบ
`std::less`, แบบ `std::greater` (min-heap) และบนฮีปของ struct ที่ไม่มี
`operator<` ให้ใช้

## ตัวอย่าง

ตัวอย่างนี้ใช้กับ `main.cpp` ที่ให้ดาวน์โหลด

### ข้อมูลเข้า

```sample-input
5
30 10 50 20 40
```

### ข้อมูลออก

```sample-output
1
0 20
```

หลัง `push` ทั้งห้าตัว อาเรย์คือ `50 40 30 10 20` ซึ่งเป็นฮีปที่ถูกต้อง
`is_heap()` จึงคืน `1` จากนั้น `raw_swap(0, 4)` สลับรากกับช่องสุดท้าย อาเรย์
กลายเป็น `20 40 30 10 50` รากจึงสำคัญน้อยกว่าลูกของมัน `is_heap()` คืน `0`
และ `top()` คืน `20`

## การทดสอบใน grader

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป (ซ่อมอาเรย์ด้วย `fixUp` ตามปกติ) |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมด โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `raw_push x` | ต่อ `x` ท้ายอาเรย์โดยไม่ซ่อม |
| `raw_swap i j` | สลับช่อง `i` กับ `j` โดยไม่ซ่อม |
| `is_heap` | พิมพ์ผลของ `is_heap()` |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะพิมพ์ `is_heap()` อีกครั้งแล้วไล่นำสมาชิก
ออกจากฮีปตามลำดับ จึงเป็นการตรวจทั้งอาเรย์ ไม่ใช่แค่คำตอบที่พิมพ์ไป

ขอบเขตของข้อมูล: แต่ละชุดทดสอบมีไม่เกิน 3 บล็อก แต่ละบล็อกมีสมาชิกไม่เกิน
30,000 ตัว และมีคำสั่งไม่เกิน 2,700 คำสั่ง สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่
เกิน 10⁶ และชนิด `long long` ไม่เกิน 4 × 10⁹
