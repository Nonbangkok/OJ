# Queue Reverse

คลาส `CP::queue<T>` ในไฟล์ `{{ds}}` เก็บข้อมูลด้วย <b>ring buffer</b> นั่นคือ
อาเรย์ `mData` ขนาด `mCap` ช่อง เก็บสมาชิก `mSize` ตัว โดยสมาชิกตัวหน้าสุดอยู่
ที่ `mData[mFront]` และตัวถัดไปวนไปทางขวาแบบวงกลม คลาสนี้ยังมีตัวแปรสมาชิก
<b>`int aux`</b> ซึ่งยังไม่มีฟังก์ชันใดใช้งาน

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T>
void CP::queue<T>::reverse();
```

ที่ <b>กลับลำดับของสมาชิกทั้งคิว</b> ให้ตัวที่อยู่หน้าสุดไปอยู่หลังสุด และตัวที่
อยู่หลังสุดมาอยู่หน้าสุด โดยใช้เวลา <b>$O(1)$</b> ต่อการเรียกหนึ่งครั้ง

เวลา $O(1)$ ทำให้ย้ายข้อมูลจริงไม่ได้ เพราะการสลับสมาชิก `mSize` ตัวใช้เวลา
$O(n)$ แนวคิดที่ใช้ได้คือ <b>จำไว้ว่าตอนนี้คิวถูกอ่านกลับทางอยู่หรือไม่</b>
ด้วยตัวแปร `aux` แล้วให้ฟังก์ชันอื่นที่ต้องรู้ทิศทางของคิวตีความ `mData` ตามค่า
`aux` นั้น ด้วยเหตุนี้โจทย์จึงย้ายฟังก์ชัน `front`, `back`, `push` และ `pop`
มาไว้ใน `{{submission}}` ให้คุณแก้ได้ด้วย

สังเกตว่า `expand` ซึ่งขยายอาเรย์เมื่อที่ไม่พอ จะคัดลอกข้อมูลตามลำดับทาง
กายภาพเดิม (เริ่มจาก `mFront` วนไป) และไม่แตะ `aux` ดังนั้นความหมายของ `aux`
ยังคงเดิมหลังการขยาย

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ <b>ไม่ใช่</b> โปรแกรมที่
ระบบใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก $n$ แล้วอ่านสมาชิก $n$ ตัวมา `push` ลง
คิวตามลำดับ จากนั้นเรียก `reverse()` หนึ่งครั้ง แล้วพิมพ์ค่าที่ได้จาก `front()`
และ `back()` ตามด้วยสมาชิกทั้งหมดของคิว

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะ

* อ่าน <b>ชุดคำสั่ง</b> และเรียก `push`, `pop`, `front`, `back`, `size` สลับกับ
  `reverse()` หลายครั้ง ไม่ใช่เรียก `reverse()` แค่ครั้งเดียวตอนท้าย
* สร้างคิวจากชนิดข้อมูลมากกว่าหนึ่งชนิด เช่น `CP::queue<int>`,
  `CP::queue<std::string>` และ `CP::queue<long long>`
* คัดลอกคิวด้วย copy constructor และ copy assignment แล้วตรวจว่าคิวต้นฉบับ
  ไม่เปลี่ยน

ดังนั้นถ้าคุณแก้ `front`, `back`, `push` หรือ `pop` แล้วทำให้พฤติกรรมเดิมของ
ฟังก์ชันเหล่านั้นเสียไป ระบบจะจับได้

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงคิว<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่
`push` ลงคิว

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ได้จาก `front()` และ `back()` หลังเรียก `reverse()` หนึ่ง
ครั้ง คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงสมาชิกทั้งคิวตามลำดับ โดยวนพิมพ์ `front()` แล้ว `pop()` จน
คิวว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
5
10 20 30 40 50
```

```sample-output
50 10
50 40 30 20 10
```

## คำอธิบายตัวอย่างที่ 1

หลังเรียก `reverse()` คิวที่เคยเป็น $10, 20, 30, 40, 50$ จะกลายเป็น
$50, 40, 30, 20, 10$ ทำให้ `front()` คืน $50$ และ `back()` คืน $10$

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจาก
คิวว่างและระบุชนิดข้อมูลของตัวเอง ภายในบล็อกจะมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` เข้าท้ายคิว (ตามทิศทางที่มองเห็นในขณะนั้น) |
| `pop` | นำสมาชิกตัวหน้าสุดออก (ถ้าคิวว่างจะข้ามคำสั่งนี้) |
| `front` | พิมพ์สมาชิกตัวหน้าสุด |
| `back` | พิมพ์สมาชิกตัวหลังสุด |
| `reverse` | เรียก `reverse()` |
| `size` | พิมพ์จำนวนสมาชิก |
| `copy` | คัดลอกคิว แล้วพิมพ์ข้อมูลของสำเนา โดยคิวต้นฉบับต้องไม่เปลี่ยน |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะนำสมาชิกที่เหลือออกจากคิวทั้งหมดและ
พิมพ์ตามลำดับ จึงเป็นการตรวจลำดับของคิวทั้งคิว ไม่ใช่แค่หัวและท้าย
