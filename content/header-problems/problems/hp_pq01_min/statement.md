# Priority Queue Min

คลาส `CP::priority_queue<T, Comp>` ในไฟล์ `{{ds}}` เก็บข้อมูลเป็น
<b>ไบนารีฮีป</b> (binary heap) บนอาเรย์: `mData` มีที่ว่าง `mCap` ช่อง เก็บสมาชิก
จริง `mSize` ตัวที่ดัชนี `0` ถึง `mSize - 1` โดยปุ่มที่ดัชนี `i` มีลูกอยู่ที่
ดัชนี $2i + 1$ และ $2i + 2$ และมีพ่ออยู่ที่ดัชนี $\lfloor (i - 1) / 2 \rfloor$

ลำดับความสำคัญไม่ได้ตัดสินด้วย `operator<` แต่ตัดสินด้วยอ็อบเจกต์เปรียบเทียบ
`Comp mLess` ที่คลาสเก็บไว้ โดย `mLess(a, b)` เป็นจริงเมื่อ `a` <b>สำคัญน้อย
กว่า</b> `b` ฮีปรักษาเงื่อนไขว่า <b>ทุกปุ่มสำคัญไม่น้อยกว่าลูกทั้งสองของมัน</b>
ดังนั้นสมาชิกที่สำคัญที่สุดจึงอยู่ที่ `mData[0]` เสมอ ซึ่งก็คือค่าที่ `top()`
คืนให้

สังเกตว่า `Comp` เปลี่ยนความหมายของคำว่า "สำคัญ" ได้ทั้งหมด เช่น
`CP::priority_queue<int, std::greater<int>>` จะกลายเป็น min-heap ที่ `top()`
คืนค่าจำนวนเต็มน้อยที่สุด และโปรแกรมตรวจยังใช้ฮีปของ struct ที่
<b>ไม่มี `operator<`</b> ให้ใช้เลย ดังนั้นการเปรียบเทียบทุกจุดในคำตอบของคุณต้อง
ผ่าน `mLess` เท่านั้น

## คำอธิบาย :

งานของคุณคือเขียนฟังก์ชัน

```cpp
template <typename T, typename Comp>
const T &CP::priority_queue<T, Comp>::min() const;
```

ที่คืน <b>การอ้างอิง</b> ไปยังสมาชิกที่ <b>สำคัญน้อยที่สุด</b> ในฮีป ถ้าฮีปว่าง ให้
`throw std::out_of_range("index out of range")` เหมือนที่ `top()` ทำ

ข้อสังเกตที่ช่วยลดงานลงครึ่งหนึ่ง: ถ้าปุ่มหนึ่งมีลูก ปุ่มนั้นจะสำคัญไม่น้อย
กว่าลูกของมัน แปลว่า <b>สมาชิกที่สำคัญน้อยที่สุดต้องเป็นใบของต้นไม้</b> คุณจึง
ไล่ดูเฉพาะดัชนี `mSize / 2` ถึง `mSize - 1` ก็พอ (เวลา $O(n)$ ถือว่าผ่านสำหรับ
ข้อนี้)

ไฟล์ `{{ds}}` ยังมีฟังก์ชัน `all_equal()` ที่เขียนไว้ให้แล้ว ซึ่งบอกว่าสมาชิก
ทุกตัวในฮีปสำคัญเท่ากันหรือไม่ โดยเทียบ `top()` กับ `min()` ของคุณ ถ้า `min()`
เลือกผิดตัว ฟังก์ชันนี้ก็จะตอบผิดไปด้วย

## คำอธิบายฟังก์ชัน main :

ไฟล์ `main.cpp` ที่ให้ดาวน์โหลดเป็นโปรแกรมทดลองสั้น ๆ ไม่ใช่โปรแกรมที่ระบบ
ใช้ตรวจ โปรแกรมนี้อ่านจำนวนสมาชิก `n` แล้วอ่านสมาชิก `n` ตัวมา `push` ลงฮีป
ตามลำดับ จากนั้นพิมพ์

1. บรรทัดแรก: ค่าที่ได้จาก `top()` และ `min()` คั่นด้วยช่องว่าง
2. เรียก `pop()` หนึ่งครั้ง แล้วพิมพ์ `top()` และ `min()` อีกครั้ง

โปรแกรมที่ระบบใช้ตรวจเป็นโปรแกรมของผู้ออกข้อสอบ ซึ่งจะอ่าน <b>ชุดคำสั่ง</b> และ
เรียก `min()` สลับกับ `push`, `pop`, `top`, `size`, การคัดลอกฮีป และการตรวจ
เงื่อนไขของฮีปหลายพันครั้ง ทั้งบนฮีปแบบ `std::less`, แบบ `std::greater`
(min-heap) และบนฮีปของ struct ที่ไม่มี `operator<`

## Input :

ข้อมูลนำเข้าในหัวข้อนี้เป็นของ `main.cpp` ที่ให้ดาวน์โหลด<br>
บรรทัดแรก : รับจำนวนเต็ม $n$ แทนจำนวนสมาชิกที่จะ `push` ลงฮีป<br>
บรรทัดที่สอง : รับจำนวนเต็ม $n$ จำนวน คือ $a_1, a_2, \ldots, a_n$ ตามลำดับที่ `push` ลงฮีป

## Output :

มีทั้งหมด $2$ บรรทัด โดย<br>
บรรทัดแรก : แสดงค่าที่ได้จาก `top()` และ `min()` คั่นด้วยช่องว่าง<br>
บรรทัดที่สอง : แสดงค่าที่ได้จาก `top()` และ `min()` หลังเรียก `pop()` หนึ่งครั้ง คั่นด้วยช่องว่าง

## Examples :

### ตัวอย่างที่ 1

```sample-input
6
10 40 20 50 30 20
```

### ข้อมูลออก

```sample-output
50 10
40 10
```

## คำอธิบายตัวอย่างที่ 1

ฮีปเก็บ `{10, 40, 20, 50, 30, 20}` สมาชิกที่สำคัญที่สุดคือ `50` และที่สำคัญ
น้อยที่สุดคือ `10` หลัง `pop()` หนึ่งครั้ง `50` ถูกนำออกไป ทำให้ `top()` คืน
`40` ส่วน `min()` ยังคืน `10`

## การทดสอบใน grader :

ข้อมูลเข้าของ grader เป็นชุดคำสั่ง ประกอบด้วยหลายบล็อก แต่ละบล็อกเริ่มจากฮีป
ว่าง และระบุชนิดข้อมูลกับตัวเปรียบเทียบของตัวเอง ภายในบล็อกมีคำสั่งผสมกันดังนี้

| คำสั่ง | ความหมาย |
|---|---|
| `push x` | ใส่ `x` ลงฮีป |
| `pop` | นำสมาชิกที่สำคัญที่สุดออก (ถ้าฮีปว่างจะข้ามคำสั่งนี้) |
| `top` | พิมพ์สมาชิกที่สำคัญที่สุด |
| `size` | พิมพ์จำนวนสมาชิก |
| `fill` | สร้างสมาชิกจำนวนมากด้วยตัวสร้างเลขสุ่มของ grader เอง แล้ว `push` ทั้งหมด |
| `copy` | คัดลอกฮีปด้วย copy constructor และ copy assignment แล้วไล่เอาสมาชิกออกจากสำเนาทั้งหมดเพื่อตรวจลำดับ โดยฮีปต้นฉบับต้องไม่เปลี่ยน |
| `check` | พิมพ์ว่าอาเรย์ยังมีสมบัติของฮีปอยู่หรือไม่ พร้อมจำนวนสมาชิก |
| `min` | พิมพ์ค่าที่ `min()` คืน (ถ้าฮีปว่าง ต้องโยน `std::out_of_range`) |
| `all_equal` | พิมพ์ผลของ `all_equal()` ซึ่งเรียก `min()` ของคุณ |

เมื่อหมดคำสั่งของบล็อกหนึ่ง grader จะตรวจสมบัติของฮีปอีกครั้งแล้วไล่นำสมาชิก
ออกตามลำดับความสำคัญ จึงเป็นการตรวจทั้งฮีป ไม่ใช่แค่ค่าที่พิมพ์ไป

## Constraints :

* แต่ละชุดทดสอบมีไม่เกิน $3$ บล็อก
* แต่ละบล็อกมีสมาชิกไม่เกิน $n \leq 20{,}000$ ตัว
* แต่ละบล็อกมีคำสั่งไม่เกิน $q \leq 3{,}500$ คำสั่ง
* สมาชิกชนิด `int` มีค่าสัมบูรณ์ไม่เกิน $10^6$
* สมาชิกชนิด `long long` มีค่าสัมบูรณ์ไม่เกิน $4 \times 10^9$
